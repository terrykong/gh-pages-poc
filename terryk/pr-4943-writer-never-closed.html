Nothing stops the writer process each advantage stage starts

NVIDIA-NeMo/RL #4943 · all permalinks pin head 85ec597.

Before
Writers held no process, so it did not matter that the stage's writers were never closed.
This PR
Each stage process now starts a writer process on its first chunk, but only the controller's own writer — which never starts one — is closed at shutdown.
Status
Open — not fixed in this PR. Raised in the review comment linked below; the fix shown is proposed.

Two pages on this PR — this one: who closes the writer process.

The stage's writer is built with background=True in AdvantageComputer.__init__. Neither it nor AdvantageActor has a close. Shutdown closes only the controller's merge writer, so the new JsonDebugWriter.close never runs on a writer that owns a process. The DebugWriter docstring still says the controller closes writers at shutdown.

With no pool the writer lives in the controller and is cleaned up only by Python's exit hook. Unit tests that build an AdvantageComputer with a dump dir also start one each and never stop it.

What would fix it — proposed, not in the PR

Where the fix lands: RL only, three files. Add a close to AdvantageComputer, an RPC for it on AdvantageActor, and call it from teardown. Nothing below is implemented or run.
