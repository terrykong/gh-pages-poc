Two pages on this PR, one question each — this one: what had to be added so images survive the trip.

SingleController (SC) is the newer training loop: one driver process owns the run, and rollout, log-prob and training workers talk through a shared key-value store called TransferQueue. Before this PR that path was text-only — a run with images would build the prompt, expand the image placeholder tokens, and then hand the model a prompt with nowhere to get the pixels from.

Almost none of the machinery here is new. The image wire format, the packing helpers, the token-mask helper and the column registration all shipped earlier, most of them in #2957 (explained on its own page). What this PR adds is about ten short call sites that point the SC path at that existing machinery — which is what the PR description means by “pipecleaning”. The figure separates the two: gray is what was already there, green is what this PR wrote.

What was already there, and what this PR wrote

Two things in the green boxes are more than a call. Step 2 extends a register_partition call that was already registering the text columns — the image names are appended to a list that existed. And step 4 also deletes the check that used to reject image batches outright, which is its own page. Everything else is a line or two that hands existing helpers the data they were written for.

The one whose position matters

What the warmup actually registers

The list is not hand-written. It is two sets of column names joined together — the ones that ride as jagged per-sample data, and the ones that are one value per token:

partition_fields = fields_with_optional_routed_experts(SC_ROLLOUT_SCHEMA_FIELDS, ...) if processor is not None: # only a VLM run adds these partition_fields.extend( sorted(PACKED_MULTIMODAL_FIELDS | PER_TOKEN_MULTIMODAL_FIELDS) # 12 names ) dp_client.register_partition(partition_id=..., fields=partition_fields, ...)

setup.py:1375-1394 — the 12 names live in multimodal_utils.py:122 and :131.

Two of those names carry the shapes that make the rest readable. An image column is jagged — sample 0 might hold two pictures and sample 1 none — so it travels as one flat blob, and the per-row shapes needed to cut it back up travel separately in the row tags (payload.py:221). The store cannot work those shapes out on its own, which is why they are shipped by hand.

The shape tag is the part that is easy to miss. The image column is jagged — one prompt may carry two pictures and another none — so it crosses as a single flat blob, and the per-row shapes travel beside it in the row tags rather than in the column itself. The store cannot work those shapes out on its own, which is why they are shipped by hand (payload.py:221). Rebuild is per row: a row whose tag is absent comes back with no pictures (multimodal_utils.py:280), and it only raises when no row in the batch has one (:263-264).

So what. A VLM run on SingleController now works end to end, and the shipped recipe is the 8-node CLEVR one added in this PR. Almost all of it is new call sites into machinery that already existed, which is why the diff is small for what it turns on. The one piece worth remembering is the warmup: it is the only change here whose position matters rather than its contents. Registering the column names during setup is what stops concurrent writers from racing to name the same column — and a race like that would have shown up as an occasional failure under load, not as a clean error on the first run.
