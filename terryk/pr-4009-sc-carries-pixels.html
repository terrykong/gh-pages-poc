Two pages on this PR, one question each — this one: what was actually stopping SingleController from running VLMs.

All the code for putting images on the wire already existed. It shipped in #2957 (explained on its own page), and the older training loop used it every day. So the interesting question about this PR is not what it built — it built almost nothing. It is why SingleController, the newer loop, still could not run a vision model. The answer is that an image had five separate places to fall out of that path, and each one alone was enough to lose it.

The five leaks

What each leak looked like in the code

#before this PRwhat the image did
1 the entrypoint built a tokenizer, never a processor:
tokenizer = get_tokenizer(config.policy["tokenizer"])
(at the base)		 The processor is the thing that turns a picture into tensors. Without one the dataset never made any, so there was nothing to lose further down. silent
2 the partition registered only the text columns
(at the base)		 TransferQueue learns a column name the first time somebody writes it. With several workers writing at once, who names the image column first is a race. silent
3 input_ids = torch.cat([m["token_ids"] for m in message_log])
(at the base)		 Takes the token ids and nothing else. The prompt still had its image placeholder tokens expanded, so the model was handed placeholders with no picture behind them. silent
4 if isinstance(v, torch.Tensor) or (isinstance(v, np.ndarray) and ...)
(at the base)		 Images travel as PackedTensor, a plain class — not a torch.Tensor. So this filter dropped the image column on the floor with no error. silent
5 raise NotImplementedError("train_microbatch does not support multimodal models…")
(at the base)		 The one that stopped the run instead of spoiling it. Why it could be deleted is the other page. loud
So what. Four of the five leaks lose the picture without saying anything. A run that hit any of them would train happily, report normal-looking loss, and quietly be a text-only run on a vision model — the failure you find weeks later in an accuracy number, not in a log. The fifth leak is the only reason that never happened: the trainer refused multimodal outright, so the four silent ones were unreachable. That ordering is worth holding on to when reading the diff. Deleting the loud check on its own would not have made SingleController work — it would have made it fail quietly instead of loudly. All five had to close together, which is why a PR that adds barely any new code is the one that turns the feature on.
