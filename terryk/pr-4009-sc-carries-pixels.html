Two pages on this PR, one question each — this one: what had to be added so images survive the trip.

SingleController (SC) is the newer training loop: one driver process owns the run, and rollout, log-prob and training workers talk through a shared key-value store called TransferQueue. Before this PR that path was text-only — a run with images would build the prompt, expand the image placeholder tokens, and then hand the model a prompt with nowhere to get the pixels from. Making it work took changes in four places, and they are not interchangeable: one of them has to happen before the others or the run races itself. The wire format for images was already built in #2957 and is explained on its own page; this PR is about getting SC to use it.

The four places, and the one that must go first

What step 3 actually registers

The list is not hand-written. It is two sets of column names joined together — the ones that ride as jagged per-sample data, and the ones that are one value per token:

partition_fields = fields_with_optional_routed_experts(SC_ROLLOUT_SCHEMA_FIELDS, ...) if processor is not None: # only a VLM run adds these partition_fields.extend( sorted(PACKED_MULTIMODAL_FIELDS | PER_TOKEN_MULTIMODAL_FIELDS) # 12 names ) dp_client.register_partition(partition_id=..., fields=partition_fields, ...)

setup.py:1375-1394 — the 12 names live in multimodal_utils.py:122 and :131.

Two of those names carry the shapes that make the rest readable. An image column is jagged — sample 0 might hold two pictures and sample 1 none — so it travels as one flat blob, and the per-row shapes needed to cut it back up travel separately in the row tags (payload.py:221). The store cannot work those shapes out on its own, which is why they are shipped by hand.

Following one prompt group through

Two prompt groups, three writers, twelve image column names. Group A has one picture, group B has none — the case worth watching, because the column is missing for B:

stepgroup A (1 image)group B (no image)

trainer reads it backrebuilt from blob + shape tagnothing to rebuild

Group B is the interesting one. Its rows simply have no image column, and the code that rebuilds images is written to tolerate that — it treats a row with no shape tag as a row with no pictures (multimodal_utils.py:261). It only gives up when no row in the batch has one.

So what. A VLM run on SingleController now works end to end, and the shipped recipe is the 8-node CLEVR one added in this PR. The piece worth remembering is step 3: it is the only change here whose position matters rather than its contents. Registering the column names during setup is what stops three concurrent writers from racing to name the same column — and a race like that would have shown up as an occasional failure under load, not as a clean error on the first run.
