How one token that crosses two turns leaves the assistant's answer with zero tokens

two ways to tokenize the empty answer bug

Two pages on this PR, one question each. This one: why an answer can end up with no tokens.

The new path joins all turns, tokenizes once, and asks each token which characters it came from. If a token starts in one turn and ends in the next, the code notices (L533-L535) but does not raise. It falls back to a second method (L544-L550): tokenize turn 1 alone, count its tokens, and cut the full token list at that count. Those are two different tokenizations, so the count lands one token too far.

"A: " then "Paris"

The same fallback can also repeat tokens. Token counts of growing prefixes do not always grow (Qwen2.5: turns ["\n ", " \n", "xx \n", "a"] give 5 tokens where the full text has 4). It is also the only path for tokenizers that cannot report character ranges, and for the PR's own unit test, whose fake tokenizer cannot be called directly. Turns that end on a chat-template marker like <|im_end|>\n split correctly.

The fix — proposed, not in the PR

Where the fix lands: RL only, one function. _tokenize_preformatted_message_log, L494-L565. Nothing below is implemented yet. It was run locally on the cases above, and the PR's existing test still passes.

The - lines are shortened with ...; the full block is in the review's suggestion block. Each turn is tokenized on its own, so a token can never belong to two turns, and every turn decodes back to its own text. This is also what generation sees: the prompt is tokenized alone, then the model writes the answer. It deletes the broad try/except and the fallback together. For chat-template turns the ids come out the same as before.

🔴 review comment — llm_message_utils.py:494-565

So what. Plain-text or completion-style data, where a prompt ends in a space or half a word, is exactly what a "preformatted" flag invites. On that data some answers silently get zero tokens and no loss. Training looks normal while it learns less than it should. Tokenizing each turn on its own removes the problem and about 50 lines of code.
