What goes wrongWhyWhat the review asks for
A broken dataset never stops
generic_sft.py:259		 Energon treats a tolerance of 0 as "disable the check", not "fail on the first error". It also switches off a second stop in the packing loop. Set it to 100, Energon's own default, and put back the comment the change deleted.
Audio silently disappears
nemotron_multimodal.py:460		 The code works out whether the processor has an audio frontend, then never uses the answer to reject anything. Each audio sample fails later and gets skipped. Raise during setup when the frontend is missing. The value is already computed.
Media is decoded for nothing
cookers/nemotron.py:371		 The file is opened before the code decides whether it needs it, and the result is thrown away when there is no cache pool. Open only on the two paths that use the handle. Moving the call down alone breaks the metadata step, which also uses it.
Crash on an odd turn count
nemotron_tokenization.py:399		 Both user and assistant turns emit the same marker, so a conversation ending on a user turn gives an odd number. The loop reads one past the last one. Reject an odd count in the guard that already exists.
Three recipes stop loading
energon/config.py:154		 The field now accepts only null. Two recipes still set it to 64 and a third inherits from one of them. Move those recipes to the new task_encoder.packing block.
Audio runs die mid-training
nemotron_multimodal.py:679		 librosa is imported but appears in no dependency list, no extra, and not in the audio install script. Declare librosa and soxr, and refresh the lock file.
What to do with this. The three CI ones are the gate: two are red in the checks list today and the third goes red the first time anyone comments /ok to test. The six runtime ones are the reason to care beyond the gate — none of them is caught by any job, so merging with them in place means the first person to run a real Nemotron training job finds them. Five further comments on the PR are design cleanups and can land afterwards.
