Three pages on this PR, one question each — this one: the nine things that have to change first, one section each.

The review left fourteen comments. Five are design cleanups that can land afterwards. The nine below stop this from merging: three that a CI job refuses, and six that no job checks at all — those only appear once someone runs a real training job.

Caught by CI — red now, or red the first time tests run

1 The Megatron-Bridge pin points off the main branch

RL's main pins an ordinary commit on Bridge's main line. This PR moves the pin onto 3961f399, which is the head of the chcui/sage/nmvl feature branch — Bridge PR #5894 was merged into that branch, not into main. Taking it adds 42 commits and drops 45, including a Nemotron VL config fix. CI's submodule fast-forward job refuses it.

Fix: say which Bridge changes this needs, land them on Bridge main, then repin to something that fast-forwards from 5ed97996.

🔴 review comment — Megatron-Bridge submodule

2 A personal soak config turns secrets-detector red

Both flags are false positives — the detector trips on the long hyphenated path, not on a real secret. But the paths are only there because the file is one person's scratch config: it hardcodes a single filesystem for model, dataset, cache, logs and checkpoints, ships a one-off run name, and leaves the debug flag on. Its commit message is "working config?".

Fix: drop the file. That clears the job with no baseline edit. Regenerating the detector baseline would hide the warning and leave the paths in public source.

🔴 review comment — n16soak.yaml:104

3 29 of the PR's own tests fail, in the lane that collects them

Three of us ran the suite in three separate virtualenvs and got identical counts. It is not an environment artifact: two of the five files pass 100% in the same interpreter. Eighteen of the failures come from one cause — a new @stateless(restore_seeds=True) makes preencode_sample unusable outside a live Energon worker, and the tests call it directly. Five are source bugs with their own sections below.

Fix: run the suite locally, then push and comment /ok to test. For the eighteen, an autouse fixture activating a WorkerConfig beats editing 25 call sites — the same pattern this PR already uses elsewhere.

4 A broken dataset never stops the job

Energon counts consecutive failures and raises past a limit. This PR sets that limit to 0, which Energon reads as "stop counting" — its own docstring says so, and its own default is 100. The same number also switches off a second stop in the packing loop. The run is noisy, not quiet: it prints per failure, including a failed N/0 times in a row counter that can never trip. It simply never ends. The PR also deletes the comment that explained all this.

Fix: set it to 100 and restore the comment. Energon already has SkipSample for dropping bad samples cleanly, so 0 was never needed for that.

🔴 review comment — generic_sft.py:259

5 An omni run trains with no audio, and says nothing

The code works out whether the processor has an audio frontend, narrows that answer, reads it once to gate an unrelated check — and never uses it to reject anything. Those are its only three uses. The complaint happens per sample instead, deep in encoding, where the disabled tolerance swallows it. The PR's own test pins this and currently reports DID NOT RAISE.

Fix: raise during setup when the frontend is missing — the value is already computed. Fix the code rather than deleting the assertion; deleting it ships the quiet half-run.

🔴 review comment — nemotron_multimodal.py:460

6 Every media file is decoded, then thrown away

The file is opened before anything decides whether it is needed, and the result is dropped when there is no cache pool. On a WebDataset run without one, that is every image, video and audio member of every sample — and for a path-valued member it hits the filesystem during cooking. Two of the 29 test failures land here.

Fix: open only on the paths that use the handle. Do not just move the call below the cache check — the metadata step also consumes opened, so a straight move breaks it.

🔴 review comment — cookers/nemotron.py:371

7 A conversation ending on a user turn crashes

The guard rejects fewer than two markers. The loop then walks the list and reads boundaries[index + 1] on even positions, so three markers means it reaches for a fourth that is not there. Unusual in curated data, entirely normal in a scraped corpus. This is a loud crash, not corrupted training — the point is that a guard already exists and catches too few cases.

Fix: reject an odd count in the guard that is already there — one condition added to the existing raise.

🔴 review comment — nemotron_tokenization.py:399

8 Three shipped recipes stop loading

The field was int | None; it is now typed so that only null passes. That is deliberate — the PR's own test asserts an integer is rejected — but the recipes were not moved to the replacement task_encoder.packing block. Two set the value directly and a third inherits from one of them. No CI job catches it: the functional test runs the non-packing recipe, and these three are disabled for GPU-hour budget with a note saying to run them by hand.

Fix: move the two files onto task_encoder.packing. The docs guide still describes the old field too, and needs the same edit.

🔴 review comment — energon/config.py:154

9 Audio runs die once training has already started

The import is bare, so the user sees a raw ModuleNotFoundError from inside the loader rather than a message naming what to install. It is not only the resampling branch: per the comment two lines above it, the feature extractor needs librosa too, so any audio path needs it. The only thing that installs it today is this PR's own dev script, which no CI path runs. soxr is missing the same way.

Fix: declare librosa and soxr, refresh the lock file, and add them to the audio install script alongside the other audio packages.
