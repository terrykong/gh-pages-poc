Why one of the parity tests checks nothing on vLLM

NVIDIA-NeMo/RL#3422 · review comment r3839631907 · all links pinned to c2ed2fc

A model can write its thinking in two shapes. Either it writes the whole block itself — <think>…</think>answer — or the prompt already ends with <think>, so the model starts inside the block and its output has no opening tag at all: …</think>answer. A parser has to know which shape it is looking at, because in the second one there is no <think> to search for.

TRT-LLM's parser takes a flag for this. The test sets it directly (trtllm_http_server.py:74). vLLM's parsers have no such flag — they work it out from the text. So the vLLM test fakes the second shape by gluing <think> onto the front of the output (test_vllm_http_server_parity.py:301). That is the problem: gluing the tag back on turns the second shape into the first one.

What to do instead

Two options. Either is fine; the point is that the page of the test should match what it really covers.

# Option A — say out loud that the backends test different things.
# Drop reasoning_at_start from the shared table, and in the vLLM test:
#
#   vLLM parsers have no reasoning_at_start flag; they infer the shape
#   from the text. The prompt-opened-the-block case is covered on the
#   TRT-LLM side only, where the parser can be told directly.

# Option B — pick an input where the two cases really differ.
# Keep the flag, but stop rebuilding shape 1 out of shape 2:
raw_output        = "inspect files</think>Visible answer"   # no opening tag
reasoning_at_start = True
# ...and assert that vLLM still splits it into reasoning + answer.
# If vLLM cannot do that, Option A is the honest answer.

Worth saying: the flag is used now, which it was not before — an earlier round of review found it was being ignored on the vLLM side entirely. This is the second half of that fix, not a new bug.

How I checked

No GPU, no engine, no run. The whole thing is one line of string handling copied out of the test, so anyone can re-run it in a second:

def vllm_parser_input(raw_output, reasoning_at_start):      # test_vllm_http_server_parity.py:301
    return "<think>" + raw_output if reasoning_at_start else raw_output

explicit_reasoning_answer        flag=False -> '<think>inspect files</think>Visible answer'
prompt_injected_reasoning_start  flag=True  -> '<think>inspect files</think>Visible answer'

the two parser inputs are identical: True

What has not happened: nobody has run the vLLM test lane on this branch. CI shows No tests run: Label CI:L*, so the only checks that have run are lint and doc builds. The thing to ask for before merging is one real run of the vLLM and TRT-LLM unit lanes.

So what. Nothing is broken and no training run is affected — this is a test that covers less than it appears to. The cost is future: if vLLM ever changes how it handles output with no opening <think> tag, this suite stays green and nobody finds out. The fix is a comment or a different input, not code.
