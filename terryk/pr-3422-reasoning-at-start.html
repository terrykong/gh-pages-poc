Why one of the parity tests checks nothing on vLLM

NVIDIA-NeMo/RL#3422 · review comment r3839631907 · all links pinned to c2ed2fc

A reasoning parser is not part of decoding. It is string handling that runs after the model has finished, on the way out. In NeMo-RL's TRT-LLM server you can read the whole sequence in one screen:

  1. the engine finishes and hands back token IDs — L303
  2. those tokens are decoded to one flat string — L318
  3. the reasoning parser cuts that string into thinking and answer — L328
  4. the two halves go into the reply as reasoning_content and content — L344

vLLM does the same thing in the same place, inside its chat server. So the parser only ever sees finished text. It never touches sampling, and it cannot see the prompt — which is the root of the whole problem below.

The two shapes, and why one test disappears

A model can produce its thinking in two shapes. Either it writes the whole block — <think>…</think>answer — or the prompt already ended with <think>, so the model starts inside the block and its output has no opening tag: …</think>answer. Since the parser cannot see the prompt, something has to tell it which shape to expect. TRT-LLM's parser takes a flag for that. vLLM's does not — it works it out from the text.

So the vLLM test fakes the second shape by gluing <think> onto the front of the output. That is what breaks it: gluing the tag back on turns the second shape into the first.

Where does that flag actually live? Only in the parser object — not the engine, not the model config, not the sampling params. In TRT-LLM every single mention of reasoning_at_start is inside one file, reasoning_parser.py: the registration lines, __init__, and parse(). It is baked into the parser name you pick — deepseek-r1 registers it True, qwen3 registers it False.

layer TRT-LLM vLLM
engine / sampling no such idea no such idea
model config no such idea no such idea
parser object has the flag — you set it no flag — reads the text instead

So the honest phrasing is: vLLM is not missing the capability, it is missing the knob. The flag simply does not exist anywhere in vLLM's reasoning code. It does the same job by looking at the string, which is why the next section says the prefix can just be deleted.

The fix: delete the prefix

vLLM handles shape 2 already. I first assumed the prefix was working around a missing feature. It is not. vLLM's parser has no flag, but it fully supports the behaviour — its base class checks for the opening tag and, when there isn't one, treats the text from the very start as thinking. The comment in vLLM says so outright: "For models that may not generate start token, assume the reasoning content is always at the start." 
# vLLM v0.20.0, BaseThinkingReasoningParser.extract_reasoning
parts = model_output.partition("<think>")
model_output = parts[2] if parts[1] else parts[0]   # no opening tag? keep the text as-is
if "</think>" not in model_output:
    return model_output, None
reasoning, _, content = model_output.partition("</think>")
return reasoning, (content or None)

Run it on both shapes and shape 2 comes out right without any prefix:

shape 1 (has <think>)        -> ('inspect files', 'Visible answer')
shape 2 (no <think>) RAW     -> ('inspect files', 'Visible answer')   <- what the test expects

shape 2 works WITHOUT the prefix: True

So the fix is to stop adding the prefix and pass the raw string. One line changes, and case 2 becomes a real test of the no-opening-tag shape on vLLM:

# tests/unit/models/generation/test_vllm_http_server_parity.py:301
- parser_input = "<think>" + raw_output if reasoning_at_start else raw_output
+ # vLLM has no reasoning_at_start flag: its parser infers the shape from the
+ # text, so shape 2 is passed through untouched. TRT-LLM is told via the flag.
+ parser_input = raw_output

How I checked

No GPU and no engine. Both the broken behaviour and the fix are plain string handling copied out of the two code bases, so this re-runs in a second. The collapse:

def vllm_parser_input(raw_output, reasoning_at_start):      # test file, line 301
    return "<think>" + raw_output if reasoning_at_start else raw_output

explicit_reasoning_answer        flag=False -> '<think>inspect files</think>Visible answer'
prompt_injected_reasoning_start  flag=True  -> '<think>inspect files</think>Visible answer'

the two parser inputs are identical: True

What has not happened: nobody has run the vLLM test lane on this branch. CI shows No tests run: Label CI:L*, so only lint and doc builds have run. The thing to ask for before merging is one real run of the vLLM and TRT-LLM unit lanes.

So what. Nothing is broken and no training run is affected — this is a test that covers less than it appears to. The cost is future: if vLLM ever changes how it handles output with no opening <think> tag, this suite stays green and nobody finds out. The fix is one line, and it makes the test do what its name says.
