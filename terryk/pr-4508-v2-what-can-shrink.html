What each piece does: the generator now builds the acknowledgement and seals in one step, as the code before this PR did for every call (base _checkpoint_active_generation_cut). send(key) then ends with StopIteration, which carries the acknowledgement. A failure still rolls the call back, through the generator's own except BaseException. The one change: if the batch is interrupted partway (for example by KeyboardInterrupt), calls earlier in that batch stay saved instead of rolling back. Batch size 1 already behaves this way today, and so did the code before this PR. One test, test_worker_batch_interruption_clears_rows_no_call_received, needs its expectation updated. Not run.
