Where NVFP4 rollout weights get quantized, and why #3566 moves that step to the vLLM worker

Companion illustration for NVIDIA-NeMo/RL #3566 (end-to-end TE NVFP4 training with per-token vLLM rollout), related to #3432. All permalinks pin the PR head 7eb9eb6.

Before
NeMo-RL could already serve an NVFP4 rollout. ModelOpt quantized the expert weights on the training side, and the weight transfer carried packed 4-bit data to vLLM.
This PR
Adds a second path. Training keeps BF16 parameters, the transfer carries BF16, and the vLLM worker packs the expert weights itself as they arrive.
Status
Added by this PR — both paths exist. They cannot be combined: the new path requires policy.quant_cfg=null.

Both paths end with the same thing in GPU memory: vLLM's routed-expert layer holding 4-bit packed weights plus the scales needed to read them. What differs is who does the packing, and what crosses the wire during a refit — the step after each policy update where fresh weights are copied from the trainer into the rollout engine. The old path packs early and sends small; the new path sends big and packs late.

The two paths

The byte counts come from one expert projection sized 8 rows x 48 columns. NVFP4 stores every value in 4 bits and shares one scale across each run of 16 columns, so 48 columns give 3 scale blocks per row:

one projection, 8 x 48 BF16 on the wire 8 x 48 x 2 bytes = 768 B <- new path sends this 4-bit packed 8 x 48 / 2 = 192 B block scales 8 rows x 3 blocks = 24 B ----- packed on the wire 192 + 24 = 216 B <- old path sends this

Where they converge, and what still differs

They meet inside vLLM. The new path's MoE class subclasses the ModelOpt one, so from the kernel's point of view both are the same layer holding the same packed tensors. Two things differ after that point, and they are the whole reason the new class exists:

What you trade. Packing late costs refit time: the PR reports weight transfer going from 1.8 s to 19.2 s per step, because the wire carries 3.6x more bytes and the receiver still has to pack them. You buy it back during generation — rollout runs 1.40x faster and the whole step 1.15x faster, since the smaller 4-bit model leaves far more room for the key/value cache. Policy training itself is 0.84x, because the backward pass still runs in higher precision. The two paths are mutually exclusive, so this is a choice per run, not a stack.
