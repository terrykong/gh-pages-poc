Two pages on this PR, one question each. This one: what each worker hands to vLLM.

Background. In vLLM, expert parallel size = DP × TP. So when a config asks for EP > TP, vLLM must run EP ÷ TP DP ranks as one instance. NeMo-RL starts one Ray worker per GPU, so each worker must tell vLLM which DP rank it is and where the instance's first worker listens. Dotted words have a short explanation: hover or tap them.

Each worker calls resolve_vllm_dp_group to get (vLLM DP size, its DP rank, the instance's first worker), then resolve_vllm_dp_settings picks the form vLLM wants. The sync engine cannot take data_parallel_size > 1 as an argument (llm.py), so it gets VLLM_DP_* environment variables, which vLLM reads as a fallback (parallel.py). The async engine gets the same numbers as engine arguments, with an external load balancer.

One worker, two engines: 32 GPUs, TP = 2, EP = 16 (the tp2ep16 nightly)

The driver also checks that the generation DP size is a multiple of the vLLM DP size (vllm_generation.py:256-259), so a half-filled instance fails at startup. With 32 GPUs and TP 2, generation DP is 16, and 16 is a multiple of 8.

So what. The async engine can now run EP > TP, which closes the gap #1101 tracked. Both engines get the same three numbers from one helper, so they cannot disagree on which DP rank a worker is. What is not covered yet: FP8 with vLLM DP, TP = 1 with EP > 1 on the sync engine, and the non-colocated refit (see page 2).
