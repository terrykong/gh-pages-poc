How the step number now reaches every span in a training step

NVIDIA-NeMo/RL #4607 (nemo-lens v0.3.0 bump, rl.iteration on every span, shared nv.dl.* attributes). All permalinks pin the PR head 62647d9.

Before
Only the step span and the training span carried the step number. Generation, reward, checkpointing and the other spans inside a step carried none, so "what else happened in step 412" could not be asked.
This PR
Sets the step number once per step, and every span the driver opens inside that step gets it.
Status
New feature, under review. The design works. The review asks for doc fixes and one bug fix (see the second page).
step number on every span async_save is always true

Two pages on this PR, one question each. This one: what the step number change does.

Background. NeMo-RL sends spans through the nemo-lens library. To find all the work in one step you filter on a tag, e.g. rl.iteration = 412. That filter only finds spans that carry the tag. Dotted words have a short explanation: hover or tap them.

Each training loop now opens its step inside iteration_scope(step) (for GRPO: grpo.py:3231). It puts {rl.iteration: 412} in a ContextVar (lens helpers.py:37), and a lens span processor copies it onto every span as the span starts (providers.py:42-48). No call site has to pass the number. A new span added inside the step later is covered too.

Which spans in GRPO step 412 carry rl.iteration

A span that sets rl.iteration itself keeps its own value. Validation uses this: it also runs once before training and reports 0 there. The finalize span uses it too, because it runs on its own thread, and a raw thread starts with an empty ContextVar.
