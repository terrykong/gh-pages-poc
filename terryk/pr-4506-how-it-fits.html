How prefix recovery could sit beside the vLLM worker instead of inside it

NVIDIA-NeMo/RL #4506 at d33e3628. The illustrative draft is terrykong/RL#27 (commit 9242495e), built on the review mirror. It follows the shape #5011 gave the single controller.

Before
Prefix recovery lives inside the worker. VllmAsyncGenerationWorkerImpl inherits a 957-line mixin, gains 1,211 lines and 16 prefix-only fields, and checks "are cuts on?" in 5 places. The OutputProcessor wrap sits inside the HTTP client.
Proposed
The worker builds one object, PrefixRecovery or a do-nothing NoPrefixRecovery, and calls it at fixed points. Only the progress reader knows about vLLM.
Status
Proposed, not implemented in #4506. The draft compiles but was not run; four test files need rewriting. Asked in review comment C49.

Seven pages on this PR, one question each. This one: where the prefix-recovery code should live.

Read the figure top to bottom. The top box is the worker and the hooks where it calls in. Each arrow is a call, labelled with the method. The middle row is what the worker builds once in setup_token_capture. The bottom row is the inputs that object is given, bundled as PrefixRecoveryParts. Only the bottom-right box knows about vLLM, so SGLang or Megatron would add one reader, and the Dynamo adapter reuses the same worker objects.

It folds four staged comments into one change:

  • C33, a standalone object instead of the mixin, is now this design.
  • C35, move the OutputProcessor wrap out of the client, is now VllmProgressReader.
  • C40, plain restore functions the Dynamo frontend can call, is now restore.py: plan_restore, restore_reply_usage and wrap_parser_for_restore.
  • C51, unforgettable per-call locks, now applies to state.py, which only PrefixRecovery touches.

The draft moves code as it is, so C52 (positional args[4] and args[5]) still applies to wrap_parser_for_restore and the usage step. One behavior detail: with cuts off, NoPrefixRecovery drops a cut Gym should never send. A real version should keep today's behavior or refuse it loudly.

So what. The worker goes back to serving vLLM, and prefix recovery becomes one object with a short list of entry points. The next backend writes one progress reader instead of copying a mixin, and Dynamo's frontend calls the same restore functions as the native server. It is mostly a move, so it adds no lines to the stack. The draft shows that it fits; the author still owns making it run.
