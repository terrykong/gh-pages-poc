Sending the whole object minus its tensors: how a PackedTensor now crosses the replica broadcast

On NVIDIA-NeMo/RL #4107, stacked on #4106. Links pinned to 4fb9fbc; deleted code is pinned at the base e347801.

Before
The image data was flattened to one row per sample, so an image shared by several samples crossed the wire once per sample. The receiving ranks rebuilt the object from a hand-written list of fields, and the sharing information was not on that list.
This PR
Splits the value in two: the object with its tensors removed travels as a pickled header, and the distinct images travel beside it as one flat block of numbers.
Status
Fixed by this PR. Each distinct image now crosses once, and the receiving ranks keep the sharing information instead of losing it.

Three pages on this PR, one question each — this one: what the change actually does.

One rank in a group holds a training batch and has to hand every other rank the same thing. Image data travels as a PackedTensor, which is two things in one object: a list of distinct images, and bookkeeping saying which sample uses which image. If four samples show the same picture, the list holds it once and four entries point at it. The question this PR answers is what to put on the wire so the other ranks end up with that same arrangement.

The same batch, before and after

Take four samples and two distinct images: image A is 6 numbers and samples 0, 1 and 2 all use it; image B is 12 numbers and only sample 3 uses it.

Why the old way lost the sharing

The old descriptor was a hand-written list of fields, so the receiving side rebuilt the object by calling the constructor with whatever was on that list. The three bookkeeping fields were not on it. In the case where a rank had no images at all, the old code rebuilt with PackedTensor([None] * n_rows, ...) — a fresh object with the sharing information simply absent (base worker_mixin.py:241-251, linked at the base since this code is gone at head).

Sending copy(self) with the tensors emptied removes that whole class of problem: any field added to PackedTensor later rides along without anyone updating a list. That is what the docstring means by “the tensor-free header retains every other instance attribute.”

What this buys. On the wire, a picture shared by k samples goes from k copies to one — in the small example above, 30 numbers to 18. On the receiving ranks the saving is the same, because they rebuild views over one block instead of materializing a copy per sample. And a rank that gets no images now ends up with the same kind of object as everyone else, rather than one silently missing its bookkeeping.
