Three pages on this PR, one question each — this one: what the change actually does.

One rank in a replica group holds a batch and has to hand every other rank the same thing. It goes in two hops: a small description of the batch via broadcast_object_list, then the numbers themselves via torch.distributed.broadcast. Image and video data travels as a PackedTensor, which stores one copy of each distinct image plus a little bookkeeping saying which samples point at it. Before this PR, the description was a hand-written list of fields, and the other ranks rebuilt the object from just those fields. This PR sends the object itself, with its tensors taken out.

Same batch, both ways: 5 samples, 2 images

Five samples. Samples 0, 2 and 4 were given the same image A, shape (2, 4), 8 floats. Samples 1 and 3 share image B, shape (3, 4), 12 floats. The PackedTensor stores each image once and records who points at what.

# the object on the sending rank tensors = [A, B] # A: (2,4) = 8 floats, B: (3,4) = 12 floats _segment_indices = [0, 1, 0, 1, 0] # sample i uses tensors[_segment_indices[i]]
BEFORE to_wire() builds one row per sample, so a shared image is copied per sample row 0 → A (8) row 1 → B (12) row 2 → A (8) row 3 → B (12) row 4 → A (8) payload = 8 + 12 + 8 + 12 + 8 = 48 floats receiving rank calls from_wire(…) → gets 5 separate images back, _segment_indices is None — the fact that 0, 2 and 4 were the same image is gone AFTER broadcast_parts() ships self.tensors, one entry per distinct image tensors[0] → A (8) tensors[1] → B (12) payload = 8 + 12 = 20 floats receiving rank calls rebuild_from_broadcast_parts(shapes, payload) _segment_indices = [0, 1, 0, 1, 0] — came over inside the header, untouched

Sender: broadcast_parts · receiver: rebuild_from_broadcast_parts · the old row-per-sample encoder is still used by the queue path: to_wire.

The receiving side does not copy anything. It walks the shapes, and for each one takes a window of the flat payload and reads it back at the right shape — so the two images are views into the one buffer that arrived:

offset = 0 for shape in [(2,4), (3,4)]: numel = 2*4 = 8 # then 3*4 = 12 tensors.append(payload.narrow(0, offset, numel).view(shape)) offset += numel # 0 → 8 → 20 if offset != payload.numel(): # 20 != 20 → no error; a mismatch raises here

Two things got better at once. The other ranks now end up with the same object the sender has, including the bookkeeping that says which samples share an image — before, they got five separate copies and no way to tell. And because only distinct images cross, the wire shrinks by whatever your duplication rate is: 48 floats down to 20 in the example above, and a batch where every sample shares one image sends one copy instead of one per sample. If you add a field to PackedTensor later, you no longer have to remember to add it to the broadcast too — and if you add a tensor field, the sender raises instead of quietly sending it the slow way.
