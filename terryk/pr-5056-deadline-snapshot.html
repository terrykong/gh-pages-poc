What a run keeps when it stops at the checkpoint deadline

Two pages on this PR, one question each. This one: what the PR changes at the deadline.

Before
At the deadline the run saved a trainer checkpoint and stopped at once. The background snapshot task was cancelled, so the environment's unfinished turns were never saved and a restart redid them.
This PR
After that trainer checkpoint, the run takes one forced environment snapshot, then stops. A new key lets a run save environment state only at the deadline.
Status
New feature, works as described. The review asks for a smaller version (about 70 fewer lines), one doc fix, and for the two deadline saves to overlap; no correctness bug blocks it.
Background. With turn-level recovery, part of a run's state lives in the environment (the tool or game server a model talks to over many turns). A trainer checkpoint saves the model and optimizer, but not that state. Only a rollout snapshot saves it. The checkpoint deadline makes a run save and exit before the job's time limit. Dotted words have a short explanation: hover or tap them.

When the deadline is due, the train loop saves a trainer checkpoint at the end of that step. Publishing it calls trainer_checkpoint_published(), which wakes a background task to snapshot the environment. Before this PR, the loop then hit break, and teardown cancelled that task before it could save. This PR has the train loop take the snapshot itself, in save_at_deadline(), before it breaks.

The last seconds of a run, before and after

The PR also adds a key that decides whether the environment is snapshotted after every trainer checkpoint, or only at the deadline. Turn-level recovery no longer needs a timer (rollout_snapshots_enabled() turns snapshots on for it):

_finish_pending_save publishes step_7 first when the save is still finishing in the background, because a snapshot must point at a published trainer checkpoint. The review asks for these cuts (none are in the PR yet):

  • save_at_deadline() repeats the try / log / re-raise code of the background loop. One shared _attempt() helper saves about 12 lines.
  • Delete save_reserve_seconds (below), merge a duplicate test, share setup across three new tests, and keep the docs to one table.
  • Overlap the two saves. Today the snapshot waits until the trainer checkpoint’s weights are fully on disk. Nothing in it reads the weights, so take it inside the trainer save, into tmp_step_N, while the weights are still being written.
