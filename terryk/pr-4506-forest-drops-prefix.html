Six pages on this PR, one question each — this one: why a restored prefix is lost when forest training is on.

Background: how Gym links one model call to the next.

Token capture records the exact tokens of every model call, so training sees what the model really produced. To reuse those tokens, Gym links each call to the call before it in the same rollout. Each call reaches the vLLM worker with an admission: Gym's note saying which rollout the call belongs to, which earlier call it continues, and, after a restore, the saved prefix to resume (generation_cut). The setting parent_resolution picks how Gym finds that earlier call (nemo_gym.py:1174):

Default (fingerprint)Forest training (source_history)

Made fora chat that only grows: each prompt is the last prompt, plus the last answer, plus a new messageagents that edit their own history: they summarize old turns, start sub-agents, or retry. One rollout's calls form a tree instead of one chain, and training keeps the chosen branches.
What Gym sendsmode="token_in" with the earlier tokens. The worker always continues from them.mode="candidate" ("this call may continue that one"), plus two fingerprints. RL decides.

request_replay is that first fingerprint. It has nothing to do with router replay, and it is not the message text. It holds one (role, hash) pair per message of this request, as the agent sent it, plus a hash of the chat-template options (Gym records.py:177-205). The second fingerprint, candidate_replay, holds the message count and one hash for the earlier call's messages. RL's decide_capture_input compares the two (capture_context.py:43-89):

  • If the new request is the earlier call's messages, plus new messages that start right after the model's answer, RL continues from the earlier tokens.
  • Otherwise RL starts a new chain from the rendered text.

With forest training, every call carries request_replay, so every call goes through this decision. Either way, the decision builds a new admission, and that new admission never copies generation_cut. That is the bug below. Dotted words have a short explanation: hover or tap them.

Example: one parent, two possible next calls. Parent call P sent [system S, user U1] and answered A1. Gym saved P's candidate_replay summary: 3 messages, and one hash over (S, U1, A1) (external_capture.py:352).

Gym also compares the two chat-template hashes. If they differ, it starts a new chain even when the messages match (external_capture.py:146-158).

Gym attaches the saved prefix to the call's admission and then deletes its own copy (Gym model.py:449-457, restored_cuts.take), so it is offered exactly once. With forest training, Gym links calls by source history (nemo_gym.py:1174-1176), so the admission carries request_replay. The worker sends any such admission through decide_capture_input (vllm_worker_async.py:2176-2203), which builds a new admission and leaves generation_cut out (capture_context.py:43-89). The worker's own comment says so: "A candidate decision rebuilds the admission without a cut".

Same restored call, two kinds of admission

Nothing is wrong with the tokens the run trains on: the call just decodes its whole reply again, as turn recovery would. But the run pays for prefix mode (the extra snapshot work) and gets none of its benefit. The restore counters stay at zero, so it looks as if no call was ever cut. The chunk rows also stay in TQ until the next restore clears rows nothing points to.

What would fix it — proposed, not in the PR

Nothing below is implemented.

Where the fix lands: RL only, one function. validate_single_controller_config in config.py refuses the combination at setup, next to the existing top_logprobs refusal. No Gym change: Gym is right to hand the cut to every admission; the worker is the one that drops it.

With this, a run that sets both fails at setup with a clear message, before any GPU work. The longer-term fix is to carry generation_cut through decide_capture_input so forest runs can use prefix recovery too; the setup refusal is the small, safe step for this PR and can be lifted when that lands.
