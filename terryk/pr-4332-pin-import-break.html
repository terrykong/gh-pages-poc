Three pages on this PR. This one: the one bug that blocks merge.

RL does not pin Megatron-LM directly. It pins Megatron-Bridge, and Bridge pins Megatron-LM (today: 6a36609). When a capture request arrives, the Megatron engine calls RL's prompt hook first. The last commit moved two new names into the import at the top of that hook (token_capture.py:122). The pinned Megatron-LM does not have them (inference_request.py:1443 has only the two older ones). So the hook raises before it reaches the "no images, pass through" branch, and the engine fails the request (dynamic_engine.py:4258).

The fix — proposed, not in the PR

Where the fix lands: RL only. Bump the Megatron-Bridge submodule to 817dd9f (Bridge #6245, merged), then remove the test scaffolding that hid the gap. No Megatron-LM or Bridge change: #7598 is already merged and already in that Bridge commit.

The submodule bump brings in Megatron-LM b4d72b7, which contains #7598 (12 commits ahead of it, 0 behind), so the import on line 122 resolves. Dropping the fixture means the tests use the real names, so a future mismatch fails in CI. The strict xfail would start passing after the bump and fail the run on purpose, so it goes too. Going back to getattr lookups would keep text capture alive on the old pin, but the media path cannot run there at all, so the bump is the one fix.

So what. As the PR stands, merging it stops all Megatron token capture, including text runs that work on main today. The PR description says the opposite ("Text capture keeps working on the current pin"). The fix already exists upstream: one submodule bump plus deleting two pieces of test scaffolding. After that, CI needs a real run (/ok to test). Only light checks have run on this head.
