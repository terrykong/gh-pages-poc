Two ways to turn a chat into tokens: the chat-template path and the new "preformatted" path

NVIDIA-NeMo/RL #4295 (split out of #4108). All permalinks pin the PR head 4fcc987.

Before
There was one way: get_formatted_message_log renders each turn with the tokenizer's chat template, then tokenizes it.
This PR
Adds a skip_chat_template=True flag. With it, the caller passes text that is already rendered, and the function only tokenizes it and cuts it into turns.

Two pages on this PR, one question each. This one: what the new path is and how it compares to the old one.

Background. SFT data is a list of chat turns (user, assistant, …). Training needs each turn as token ids, kept per turn, because only the assistant turns get a loss: the add_loss_mask_to_message_log step marks a turn's tokens for training by its role. So both paths must answer one question: which tokens belong to which turn? Dotted words have a short explanation: hover or tap them.

The old path builds the text itself. For turn i it renders turns 0..i with the chat template, keeps only the new text, and tokenizes that piece alone (L750-L752). The new path is for data where each turn's text is already written out in full. It returns early (L595-L600), joins all turns into one string, tokenizes it once, and cuts the tokens back into turns using each token's character range.

Where each path does the work

The same chat through both paths

Take one chat, user: "Hi" and assistant: "Hello", with the Qwen2.5 tokenizer. The old path renders it. To use the new path, a caller would pass the two rendered pieces directly:

turn 1 (user) turn 2 (assistant) old path text "<|im_start|>system\n…<|im_end|>\n<|im_start|>user\nHi<|im_end|>\n" "<|im_start|>assistant\nHello<|im_end|>\n" old path tokens 27 6 new path tokens 27 6 ← same ids, token for token

When every turn ends on a chat-template marker like <|im_end|>\n, no token can cross the cut, so the two paths agree. They come apart on plain text, where a turn can end in the middle of what the tokenizer treats as one token, for example "A: " followed by "Paris". That case is the next page.
