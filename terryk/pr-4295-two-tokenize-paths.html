Three pages on this PR. This one: the two paths side by side, with the data at every step.

Background. SFT data is a list of chat turns. Training needs each turn's token ids kept separately, because only assistant turns get a loss: add_loss_mask_to_message_log marks a turn's tokens for training by its role. So both paths answer one question: which tokens belong to which turn? Dotted words have a short explanation: hover or tap them.

On the left, the existing loop in get_formatted_message_log runs with the pass-through template. On the right, skip_chat_template=True returns early into the PR's helper (L595-L600). Both get the same two turns. Read across each row: the two sides hold the same data until step 2, and the answer is lost at step 4.

The same two turns through both paths

When every turn ends on a chat-template marker such as <|im_end|>\n, no token can cross a cut, so the two lanes give the same ids. They split when a turn ends in a space or half a word, as above.
