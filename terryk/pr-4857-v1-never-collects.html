Why manual_gc turns GC off for good on v1 training

NVIDIA-NeMo/RL #4857 · permalinks pin the PR head cdd9b68.

Before
No manual_gc flag. Python's automatic GC runs on every path.
This PR
Turns GC off in every Megatron policy worker at startup, but collects only inside finish_train_step, which only v2 trainers call.
Status
Open — not fixed in this PR. Raised in the review; the one-line fix is below.
1 · what manual_gc does 2 · where it never collects

Two pages on this PR. This one: which trainers never reach the collection.

The flag has two halves. Startup turns automatic GC off for every Megatron policy worker (__init__ L888). The periodic collection runs in one place only: finish_train_step L2266. That method is part of the v2 step API. The v1 trainers call the worker's train() instead, which runs its own optimizer step and never reaches L2266. examples/run_sft.py, the command in the PR description, is v1.

Which paths collect, with manual_gc_interval: 2 over 5 steps

The fix — proposed, not in the PR

Nothing below is implemented.

Where the fix lands: RL only, two files. megatron_policy_worker.py train() and teacher_worker_group.py. No Megatron change: its own manual_gc already collects inside its training loop.

@@ megatron_policy_worker.py L1655-L1660 · train(), once per call
         if not eval_mode:
             ...
             self.scheduler.step(increment=gbs)
+            # One train() call is one training step, same as one finish_train_step.
+            self._maybe_run_manual_gc()
@@ teacher_worker_group.py L175-L185 · teacher config builder
         if "router_replay" in cfg:
             cfg["router_replay"]["enabled"] = False
+        # A frozen teacher never trains, so it would never reach the manual
+        # GC collect; keep automatic GC on.
+        cfg["megatron_cfg"]["manual_gc"] = False

The first hunk sits right after the barrier every rank passes at the end of train(), so all ranks still collect together. It also covers grpo_sync, which reaches the same train(). v1 and v2 never both run for one step, so no step is counted twice. The second hunk keeps the frozen teacher on normal GC, next to where the builder already turns off other student-only features.

🟠 C2 review comment — teacher configs (anchored at :2285)

So what. With the flag on, the PR's own example (run_sft.py) runs the whole job with no garbage collection. Host memory, and GPU memory held by leftover objects, grows with every step. Any speedup measured that way is "no GC at all", not "GC together". Until the train() line lands, only v2 trainers should use the flag.
