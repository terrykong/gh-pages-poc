Four pages on this PR, one question each — this one: what the new function actually does.

Before
There was no group-level answer. Dynamic sampling used std != 0, a per-row floating-point test, to decide whether a prompt group was worth training on.
This PR
Adds a 22-line function that answers one question per prompt group — "are all the valid rewards here the same value?" — and writes that one answer to every row of the group.
Status
Added by this PR. Used only by dynamic sampling. The per-rollout leave-one-out check it sits beside is unchanged and still drives normalization.

The whole function is a loop over prompt groups. For each group it takes the rewards that are still valid, asks whether they are all one value, and stamps that single answer onto every row belonging to that group — including the invalid ones. There is no leave-one-out anywhere in it, which is the entire point: the answer must not depend on which row is asking.

One pass over two groups

is_trivial_prompt_distribution = torch.ones_like(rewards, dtype=torch.bool) L236 start with True everywhere for prompt in torch.unique(prompts, dim=0): L237 one pass per distinct prompt prompt_mask = (prompts == prompt).all(1) L238 which rows belong to it valid_rewards = rewards[prompt_mask & valid_mask.bool()] L239 drop the masked-out rows is_trivial = valid_rewards.numel() <= 1 or ( L240 0 or 1 reward -> nothing to compare valid_rewards.amin() == valid_rewards.amax() L241 otherwise: are they all equal? ) is_trivial_prompt_distribution[prompt_mask] = is_trivial L243 stamp it on EVERY row of the group

Two details do the real work. Line 239 filters to valid rows before comparing, so a response that was masked out cannot make a group look diverse. Line 243 writes to prompt_mask — all rows of the group, not just the valid ones — which is what makes the answer all-or-nothing and stops the filter from ever splitting a group.

The numel() <= 1 on line 240 quietly matters too: it short-circuits the or, so amin() is never called on an empty tensor.

What it returns at the edges

Every case below was run against the real function at 70b70e7. Nothing raises.

two groups, one trivial one not -> [True, True, True, False, False, False] one group, all same -> [True, True, True, True] one group, one differs -> [False, False, False, False] differs ONLY in a masked-out row -> [True, True, True, True] group reads as all-one-value exactly one valid row -> [True, True, True, True] nothing to compare against zero valid rows -> [True, True, True, True] numel() == 0 short-circuits empty batch -> []

The fourth row is the one worth pausing on. If the only rollout that scored differently is masked out, the group is treated as all-one-value and dropped in full. That is the right call — a reward that is not trainable cannot supply the contrast — but it means masking can change a keep into a drop, not just remove one row.

How it differs from its sibling, in one line. The per-rollout check compares each rollout against its peers and can return different answers within one group; this one compares the whole group and returns one answer for all of it. Using the first where the second belongs is exactly the bug that got caught in review — see one check or two.
