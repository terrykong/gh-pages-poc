Size review of NVIDIA-NeMo/RL #4507, stacked on #4506. Line counts are from git diff 834241af deb0e146. All permalinks pin the PR head deb0e146. Review comments are in a pending review; the links work once it is published.

Before
The base PR's prefix-recovery test killed one run and checked that the restored run trained. It never compared against a run that was not interrupted.
This PR
Adds that comparison: an uninterrupted run, then a killed-and-restored run, and a 1,037-line script that compares what they trained. Test files only.
Status
Proposed — not implemented. The test is the right idea. About 1,040 of its lines can go without dropping a check; each cut is a review comment, none applied yet.
size and reuse rows the test excuses

Two pages on this PR — this one: which lines do the checking, and which repeat code that already exists.

The test runs the same small Workplace workload twice and requires every trained row to match token for token. The checks that can fail the run are a short list: rows match, each restored prefix trained exactly once with the right length, no old prefix keys left behind, rewards are not all the same, and generation log-probs agree. Most of the remaining code prints reports, re-checks something already checked, or rebuilds a training-data dump that NeMo-RL already writes.

So what. The check this PR adds is worth having, and earlier reviews asked for it. But the prefix-recovery stack is already ~21,100 lines, and the size asks on #4506 are still open. Cutting this PR to its checks (about 1,060 lines instead of 2,098) keeps a test that is easy to read when it fails. Separately, top_p=0.000001 means rewards never reach the weights, so steps 2 and 3 cost GPU time without testing learning. That is a review comment, not on this page.
