Three pages on this PR, one question each — this one: where a number like "8 groups" comes from.

No setting says "chunks are 8 groups". Inside one training step, the pump runs a chunk loop (while groups_dispatched < target): each pass asks the sampler for one chunk, trains on it, and goes round again until the step has its 32 groups. This is not the step loop (one level up) or the micro-batch loop (inside the training of one chunk). The chunk size falls out of four things. The sampler only decides which ready groups are allowed; all samplers then share the same size rule:

max = min(groups the step still needs, max_groups_for_streaming_train) # cap: new in this PR floor = min(min_groups_for_streaming_train, max) chunk = min(number of allowed groups, max) # PPO also rounds down to its group multiple if chunk < floor: no chunk — wait 5 ms, ask again

What each sampler allows

SamplerReady groups it allows into a chunk
in_orderOnly groups made for the trainer's current step. Early groups for the next step wait.
ready_firstAny finished group generated with weights no newer than the trainer's, including ones admitted early.
weight_fifoOnly groups from the oldest weight version still in the window.
windowedAny finished group inside the staleness window; optionally newest first.

Within the allowed set, groups are taken in buffer order — the order of their slots, not the order they finished — except windowed with newest-first on.

So what. With in_order, a chunk only reaches the cap once enough of this step's groups have finished, so chunks are often smaller than the cap. With ready_first, early groups count too, so a warm buffer almost always has more than the cap ready — there, the cap is what sets the chunk size. Either way the step still trains on exactly 32 groups.
