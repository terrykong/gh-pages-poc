Where teacher inference runs in the SingleController distillation path

Companion illustration for NVIDIA-NeMo/RL #3768 (add multi-teacher on-policy distillation to the SingleController text path). All permalinks pin the PR head 359c895.

In on-policy distillation, a big frozen teacher model scores the tokens a smaller student just generated. The advantage the student trains on is simply teacher_logprob − student_logprob, so every rollout needs a teacher number attached before it can be trained on. The SingleController path already runs two loops at once: one generating rollouts, one training on them, joined by a replay buffer. So there is a real question of where the teacher call goes. This PR puts it in a place that is easy to miss: inside the replay buffer's commit(), after the rollout is written to storage but before that row is allowed to be trained on.

The older code path did the same job in a different order, and the differences all follow from that one change:

Older pathThis PR
When the teacher runsafter the rollout, before the row is handed to the bufferafter the row is written to storage, before it becomes trainable
What crosses the networkthe token tensors, through the driver and backonly row IDs — each teacher rank reads and writes storage itself
Uneven batch sizescopy the last row in memory, trim the answer afterwardswrite real temporary rows, delete them after
If the teacher failsthe row was never handed over, so nothing to undothe rows already exist, so they must be deleted and the rollout must not be re-run

Does it work?

The author ran the same 5-step recipe on both paths — same Qwen3-1.7B student and teacher, same dataset, same seed, same batch sizes, 3 nodes of 8 GPUs. Student and teacher are the same checkpoint, so a correct run must produce an advantage of essentially zero; any misrouted or misaligned teacher column would show up immediately as a non-zero gap.

The two medians differ by 9.4e-5. These were independent rollouts, so the generated tokens are not identical token-for-token even with a shared seed — this shows the two paths behave the same, not that they produced the same text. Both jobs finished with exit code 0.

Teacher cost is charged to whichever step it lands on, which makes the per-step numbers look uneven: teacher_samples came out as [64, 0, 32, 32, 32] across the five steps. The first bucket reads 22.57 s, but 16.44 s of that is one group waiting on another for the same teacher. Steady-state cost is 0.90–1.23 s.

What this costs you. A prompt group sitting in teacher inference still holds its in-flight slot and its buffer slot, so slow teachers throttle rollout generation directly, and starve training a moment later. With a single teacher the lock makes this strictly one-at-a-time — the 16.44 s of lock wait above is exactly that. Adding a second physical teacher is what buys parallelism; adding a second name for the same checkpoint does not, because both names share one lock. Worth watching teacher_lock_wait_time_s if rollout throughput drops.
