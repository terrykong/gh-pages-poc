A chunk cap cannot make a step faster when generation is faster than training — a worked example

NVIDIA-NeMo/RL #5036. All permalinks pin the PR head 391cb0fc.

Before
When generation runs ahead, the whole step is ready at once, goes to the trainer as one chunk, and generation sits idle while it trains.
This PR
Caps chunks so the trainer takes the step in small bites, hoping generation can keep working in between.
Status
Open — this model predicts no gain, only extra cost. Review comment C2 asks for one real capped vs uncapped timing run.

Four pages on this PR, one question each — this one: can a cap ever make a step faster when generation is ahead?

The question: if generation is several times faster than training, does taking 8 groups at a time instead of the whole step ever shorten a step? To answer it without hand-waving, a small simulation (code at the bottom of the page) plays out the pump's rules from the code:

  • Buffer slots come back only when the step closes (L3870).
  • With ready_first, generation may run max_staleness_versions steps ahead (default 1, used here): the gate admits a batch only while it is fewer than that many steps ahead of the trainer's version (L506, default), and that version moves only after the optimizer step (L3771).
  • The chunk loop takes everything ready, up to the max, once the floor is met (L345).
step: 32 prompt groups, floor 8, cap 8 (or none) generation: 2 groups per second → 16 s to make a whole step (6× faster than training) training: 3 s per group → 96 s of real work per step per chunk: 5 s of fixed work (a logprob pass, advantages, training setup) lookahead: ready_first, max_staleness_versions 1 → at most 1 step ahead; buffer holds 64 groups (2 steps)

Why no case beats 101 s

Every step must train 32 groups × 3 s = 96 s. Chunking cannot remove any of that work; it only adds the 5 s fixed cost once per chunk: 1 chunk → 96 + 5 = 101 s, 4 chunks → 96 + 20 = 116 s. Generation needs only 16 s per step and is already finished before the trainer asks, so the trainer never waits on it. A larger max_staleness_versions lets generation run further ahead, but the steps still take 96 s of training each, so the result is the same. Freeing generation earlier gives it more chances to work, but there is nothing on the training side for that work to speed up. The idle generation time is real, but it means too many GPUs are on generation for this ratio — the fix is to move GPUs to training (or allow more staleness), not to cut the step into chunks.

So what. When generation is ahead — the only time a cap changes anything — training is the slow side, and a cap can only add per-chunk cost (here +15 s, about 15%). The cap could still matter for something other than speed, such as lower peak memory per chunk, but that is not what the PR claims. This is a model of the rules, not a hardware timing: C2 asks the author to settle it with one real run.
The simulation code (Python, no dependencies) 
"""Tiny event simulation of the SC chunk loop vs generation, for the PR #5036 explainer.

Model (mirrors the code's rules, not its timings):
- Step = 32 prompt groups. Floor 8. Cap = None or 8.
- Generation makes 2 groups/s, one after another, whenever it is allowed to.
- Allowed = (a) the lookahead gate: groups started < (steps closed + 2) * 32, i.e. at most
  one step ahead of the step being trained (the trainer version only moves at step close);
  (b) a free buffer slot: capacity 64 = 2 steps.
- Slots come back at step close (the code today) or right after each chunk trains (the hope).
- Trainer chunk loop: take min(ready, max) if >= floor, else poll. Training a chunk of k
  groups takes 3*k + 5 s (5 s = fixed per-chunk work: logprobs, advantages, setup).
"""
import json

STEP, FLOOR, GEN_RATE, T_GROUP, T_CHUNK, CAP_SLOTS, AHEAD = 32, 8, 2.0, 3.0, 5.0, 64, 1
N_STEPS = 5


def run(cap, release_per_chunk, gate_per_chunk=False):
    dt = 0.05
    t = 0.0
    started = 0          # groups generation has started
    ready = 0            # finished, not yet taken by the trainer
    in_gen = 0.0         # progress on the group being generated
    slots_used = 0
    steps_closed = 0
    trained_this_step = 0
    train_busy_until = None
    chunk_k = 0
    gen_segments, train_segments, step_ends = [], [], []
    gen_on = None
    while steps_closed < N_STEPS:
        # trainer
        if train_busy_until is not None and t >= train_busy_until - 1e-9:
            trained_this_step += chunk_k
            if release_per_chunk:
                slots_used -= chunk_k
            train_busy_until = None
            if trained_this_step == STEP:
                steps_closed += 1
                trained_this_step = 0
                if not release_per_chunk:
                    slots_used -= STEP
                step_ends.append(round(t, 2))
        if train_busy_until is None and steps_closed < N_STEPS:
            mx = STEP - trained_this_step
            if cap is not None:
                mx = min(mx, cap)
            take = min(ready, mx)
            if take >= min(FLOOR, mx):
                ready -= take
                chunk_k = take
                dur = T_GROUP * take + T_CHUNK
                train_segments.append((round(t, 2), round(t + dur, 2), take, steps_closed))
                train_busy_until = t + dur
        # generation
        consumed = steps_closed * STEP + (trained_this_step if gate_per_chunk else 0)
        allowed = (started < consumed + (1 + AHEAD) * STEP if gate_per_chunk else started < (steps_closed + 1 + AHEAD) * STEP) and slots_used < CAP_SLOTS
        working = in_gen > 0 or allowed
        if working:
            if in_gen == 0:
                started += 1
                slots_used += 1
            in_gen += GEN_RATE * dt
            if in_gen >= 1 - 1e-9:
                in_gen = 0.0
                ready += 1
            if gen_on is None:
                gen_on = t
        elif gen_on is not None:
            gen_segments.append((round(gen_on, 2), round(t, 2)))
            gen_on = None
        t += dt
    if gen_on is not None:
        gen_segments.append((round(gen_on, 2), round(t, 2)))
    total = step_ends[-1]
    steady = [round(step_ends[i] - step_ends[i - 1], 2) for i in range(1, len(step_ends))]
    gen_busy = sum(min(b, total) - a for a, b in gen_segments if a < total)
    return dict(cap=cap, release_per_chunk=release_per_chunk, step_ends=step_ends, steady_step_times=steady,
                total=round(total, 2), gen_busy_frac=round(gen_busy / total, 3),
                gen_segments=gen_segments, train_segments=train_segments)


out = {'uncapped': run(None, False), 'cap8': run(8, False), 'cap8_hope': run(8, True), 'cap8_all': run(8, True, True)}
for k, v in out.items():
    print(k, 'step ends', v['step_ends'], 'steady', v['steady_step_times'], 'gen busy', v['gen_busy_frac'])
    print('   chunks', [(s[2], s[3]) for s in v['train_segments']])
json.dump(out, open('sim.json', 'w'))
