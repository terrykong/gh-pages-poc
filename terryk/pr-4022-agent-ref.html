NVIDIA-NeMo/RL #4022 · fix commit b99ee92e · all links pinned to b99ee92e

the stolen port the missing agent ref

Two pages on this PR, one bug each — this one: why rows came back without their agent.

Every NeMo-Gym row says which agent server should run it. Rows used to carry that answer already baked in, under the key agent_ref. Gym changed: a row now arrives carrying only task_source — the name of a dataset — and Gym works out the agent from it at dispatch time, writing agent_ref onto the row (Gym rollout_collection.py L1818-1822). That write happens inside a Ray actor, and that is where the trouble starts.

What went wrong

Green = the row that has the agent name. Red = the caller's row, still missing it. Ray gave the actor a copy, so writing to A' can never change A.

This is the part that is easy to miss when reading the code. The line that fills in agent_ref looks like it mutates the row you passed in — and inside one process it would. Across a Ray call it does not, because the actor is working on a copy that was made when the call was sent.

The fix

Send the resolved name back with the result instead of relying on the shared-object illusion. The stream used to yield three values per row; it now yields four, with the agent name in the middle. Following one row through:

# in the actor — say what you resolved, do not just write it locally yield (rowidx, nemo_gym_row["agent_ref"], nemo_rl_result, timing_metrics) # 0 {"name": "chat_bot"} # in the caller — unpack the extra value and write it onto our own copy rowidx, resolved_agent_ref, result, timing_metrics = await result_ref pending_by_rowidx[0]["agent_ref"] = {"name": "chat_bot"}

The same commit adds two checks so a future version of this bug is loud instead of silent. One prompt group is many attempts at a single prompt, so every row in it must come back with the same agent — if the name is missing, or two rows disagree, the run stops with a message that says so rather than writing a wrong value into the training record:

resolved_agent_ref = rollout_inputs[0].get("agent_ref") if not isinstance(resolved_agent_ref, dict): raise ValueError("NeMo-Gym did not return a resolved agent_ref") if any(row.get("agent_ref") != resolved_agent_ref for row in rollout_inputs[1:]): raise ValueError("NeMo-Gym resolved one prompt group to inconsistent agent_ref values")

What to take away. When a function writes to a dict you handed it, that write only reaches you if you are in the same process. Send it across a Ray call and you get a copy, so the write lands somewhere you will never read. If a remote worker figures something out, it has to return it — putting it on the argument is not a channel. The tell is code that reads a key some other process was supposed to fill in.
