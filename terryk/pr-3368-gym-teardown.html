Who shuts down the Gym servers when training crashes

Companion illustration for NVIDIA-NeMo/RL #3368 (stacked on #3367). All permalinks pin the PR head d9c789f.

A NeMo-Gym environment is a Ray actor that starts real server processes — one per configured server, launched with Popen inside the actor (Gym env.py:422). Those processes hold ports and do not go away on their own. Something has to call NemoGym.shutdown(), and if training raises halfway through, that call has to happen anyway. Before this PR the job's top-level script was the only thing that made the call — so whether your servers were cleaned up depended entirely on which script you launched.

Before: four of the six launchers never made the call

Each script name links to the line where it runs training. The two green rows call teardown themselves; the four red rows never did.

The fix: move the call inside the training function

The training body was renamed to _grpo_train_impl and a short wrapper took its name. The wrapper does one thing — run the body, and clean up on the way out, whether the body returned or raised. Every launcher gets it for free, including the four that never called teardown.

before — the body ended and that was that def grpo_train(policy, ..., processor=None): ... # about 1200 lines of training checkpointer.shutdown() # last line. environments untouched. after — same body, renamed; a wrapper owns the cleanup def _grpo_train_impl(policy, ..., processor=None): ... # unchanged, just renamed @trace_fn(RLSpanGroup.JOB, "rl.grpo.job") def grpo_train(policy, ..., processor=None): try: _grpo_train_impl(policy, ...) # raises? doesn't matter finally: shutdown_environments(task_to_env, val_task_to_env)

Real code: grpo.py:4033 (wrapper) and grpo.py:2838 (the renamed body). Same shape in distillation.py:1187.

The helper it calls is new, and it has one job beyond looping: ask each actor to stop once. Runners hand it the training map and the validation map, and those two are very often the same dict — so a plain loop would ask the same actor to stop twice.

A = the one NemoGym actor handle task_to_env = {"nemo_gym": A} val_task_to_env = task_to_env # the same dict, not a copy shutdown_environments(task_to_env, val_task_to_env) seen = set() map 1 -> A: id(A) not in seen -> ask A to stop, wait up to 10s 1 call map 2 -> A: id(A) already in seen -> skip 0 calls A stopped once

Real code: utils.py:145. The aliasing it guards against is real — run_grpo_nemo_gym.py:274-275 assigns one dict to both names.

Does it work?

Nobody has posted a run. There is no log, no before-and-after count of leftover server processes, and no link to a job that crashed and came back clean. The change is small and the reasoning holds up on reading, but "we reasoned about it" is not the same as "we watched it work".

The thing to ask for before merging is cheap: launch run_vlm_grpo.py — one of the four that had no teardown — kill it partway through, and paste the process count on the node before and after. One number each way settles it.

A catch worth knowing about. The new budget is 10 seconds (utils.py:24); when it runs out, the actor is killed outright. But the call it is timing has no time limit of its own — Gym's shutdown ends with join() on the head-server thread with no timeout. Gym signals every server at once (env.py:588), so healthy ones stop together — but each server that ignores the signal costs up to 1 second to wait for, plus up to 2 more to clean up after force-killing it. About four stubborn servers is enough to blow the budget, and the largest Gym config in the repo lists 13 servers. Kill the actor at that point and the servers still holding ports are exactly the ones that were about to be force-killed.
