Size review of NVIDIA-NeMo/RL #4762, the last PR in the partial-checkpointing stack. All permalinks pin the PR head 71d3b46; the current stack is pinned at fd86c61 (#4655 head, which includes #5011). Review comments are in a pending review; their links work once it is published.

Before
A finished save already exports its step timings as metrics (#4730). TQ save and load already get a span. On a Gym timeout, the error already names each Gym deployment that did not answer.
This PR
Adds a live span tree around each save and restore, plus 3 live gauges, a duration histogram, a 30-second progress logger and per-worker prefix spans: 1,854 added lines in one commit. The branch predates #5011 and conflicts in 7 files.
Status
Proposed — not implemented. The smaller version below is a review suggestion. Open: one span opens in one task and closes in another, so every save logs an OpenTelemetry error (C1).
Background. A rollout checkpoint save pauses new rollouts, asks every Gym deployment to prepare and commit, fences token capture on the vLLM workers, saves TQ, then publishes. The PR wants two things: see which step is slow or stuck, and see which Gym deployments have not replied. Dotted words have a short explanation: hover or tap them.
