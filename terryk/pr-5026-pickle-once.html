Why the driver now pickles the tokenizer once, not once per node

NVIDIA-NeMo/RL #5026 · permalinks pin the PR head 925d381 (code that was removed links the base, 681ca04)

Before
When a worker group starts, the driver sends the worker's constructor arguments to one helper actor per node. Ray pickled them again for every node: 8.3 MB and about 0.16 s each time, almost all of it the tokenizer.
This PR
Puts each argument over 1 MB into Ray's object store once, and sends every node a 233-byte reference instead.
Status
The speed-up works as measured (21 s → 0.07 s at 128 nodes). One bug is open in how it decides what is "over 1 MB". See the second page.
pickle once the leaked queue actor

Two pages on this PR, one question each. This one: what the change does.

Background. A worker group starts its workers in two steps. First it starts one small initializer actor per node. Each initializer then starts that node's GPU workers. Everything the workers need to be built with (config, tokenizer, a small queue) travels with step one. Dotted words have a short explanation: hover or tap them.

On main, the loop that starts the initializers passed *remote_worker_builder.args, **remote_worker_builder.kwargs straight into every .remote() call (base worker_groups.py L596-L608). Ray pickles a call's arguments each time it is made, so a 128-node job pickled the tokenizer 128 times, one after another, on the driver. The policy passes the tokenizer as a keyword argument (lm_policy.py L455-L462), and its fast tokenizer rebuilds its whole vocabulary on every pickle.

One pickle per node, versus one pickle total

The initializer code does not change. Ray turns a top-level reference argument back into its value before the actor's __init__ runs, for keyword arguments too (Ray flatten_args puts each keyword argument at the top level). So each initializer still gets a real tokenizer.
