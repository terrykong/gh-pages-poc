Three pages on this PR — this one: how big it is, and what can go.

vLLM 0.29 keeps each running request's routes in a private list, routed_experts_chunks, and only hands them out when the request ends. That list is only ever appended to. Rows already in it never change. So the rows a cut needs are simply the first N rows of that list at the moment of the cut. The PR instead copies every new piece as it arrives, carries it through the HTTP layer, and keeps it in buffers that a cut swaps, saves, or rolls back.

Two ways to get the same rows

Same tiny example as page 1: prompt 10, 11, tokens 12, 13 at the first cut. L = MoE layers, K = experts per token. Both ways give the rows [1, 2, 3]. Two reviewers checked the vLLM source: the scheduler never re-sends rows for a position, and a finished request's list is dropped in the same step as its final output, which is why a cut that races the end must use the final routes.
