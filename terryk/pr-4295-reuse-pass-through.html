Tokenizing text as-is already works in NeMo-RL. Reuse it instead of adding a second tokenizer.

NVIDIA-NeMo/RL #4295 (split out of #4108). Permalinks pin the PR head 4fcc987. Token ids come from the Qwen2.5-0.5B-Instruct tokenizer.

Before
Setting policy.tokenizer.chat_template: null swaps in a pass-through template, and the normal loop then tokenizes each turn's text as-is. That setting covers the whole run.
This PR
Adds a per-call skip_chat_template=True flag backed by a new 100-line tokenizer that joins the turns, tokenizes once, and cuts the result back into turns.
Status

Where the fix lands: RL only, one function, plus the PR's test. llm_message_utils.py: +31 / −110 lines. No change to get_tokenizer or the chat templates. When the flag is set, the loop builds the pass-through text itself (the turns joined, exactly what the pass-through template renders) instead of calling apply_chat_template. That way the tokenizer's own template is never used or changed.

In order: _join_text_parts keeps the PR's support for content written as a list of text parts. The pass-through template alone would print that list as "[{'type': 'text', …}]". The check before the loop keeps the PR's error for add_generation_prompt, and also rejects tools, which the pass-through template would quietly ignore. The join in the loop is the whole feature: it produces exactly what the pass-through template renders, and everything after it (cut out the turn's text, BOS/EOS, tokenize the turn alone) is the code every SFT dataset already runs. The result passes ruff format and ruff check. Passing chat_template= to apply_chat_template instead looks simpler, but the DeepSeek-V4 tokenizer wrapper replaces that method and ignores the argument. Through it, ["A: ", "Paris"] rendered as <｜begin▁of▁sentence｜><｜User｜>A: <｜Assistant｜></think>Paris…. The join gives "A: " | "Paris" with every tokenizer (checked through that same wrapper).

What else changes

  • BOS/EOS follow the normal flags. They are added only when missing (L719, L739). With the defaults, Qwen gives "Paris" → "Paris<|im_end|>". To keep text exactly as written, pass add_bos_token=False, add_eos_token=False.
  • The dataset's task prompt is applied, as on every other path (L650). The PR's helper silently dropped it.
  • Empty turns no longer raise. They give an empty tensor, the same as the normal path (L775-L779). Keep the PR's empty-turn check in _join_text_parts if that error matters.
  • The PR's unit test needs a real tokenizer. Its RawTokenizer has only .encode, and the loop calls apply_chat_template and the tokenizer itself. The file already loads Qwen2.5 in other tests (L998).
  • Leading-space tokenizers. On Mistral v0.3 and Llama-2, encoding each turn on its own adds a leading space to every turn after the first: ["Question: hi\n", "Answer"] decodes back as 'Question: hi\n Answer', while one joint encode keeps it exact. The chat-template path already behaves this way (its assistant chunk "Answer" also encodes to [27075], ▁Answer). Qwen2.5, Llama-3.1, Gemma-2 and Nemotron-Nano-9B-v2 decode back exactly.
  • #4108's copy becomes a wrapper. When the Nemotron encoder comes back, its _raw_tokens_and_mask (about 50 lines) can be this. It was run on the same input and gives tokens [32, 25, 220, 59604], mask [0, 0, 0, 1]:
