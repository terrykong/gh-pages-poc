Three pages on this PR, one question each. This one: when replay's own safety check kills a healthy run.

Background. Replay trusts the K captured slots to hold every token vLLM could sample (page 1). When they do not, the code must tell two cases apart: a short list (vLLM kept more tokens than K, which happens) and a broken capture (a bug). The function's own docstring says a short list is "reported, not raised on", so the token is just dropped and counted. It decides "short" by one test: do the captured probabilities add up to less than 1 − 1e-4?

Three captured lists, one rule

top_k = top_logprobs = 3 (allowed: setup only needs top_logprobs ≥ top_k, and the guide's example uses 64 / 64). On a decode batch with fewer than 8 requests, vLLM's PyTorch top-k keeps every token tied with the 3rd logit (the batch ≥ 8 Triton path keeps exactly 3). Logits for ids 17, 4, 9, 23: 2.0, 1.4, then a tie.

  1. Rows A and B are the same event, a tie at the cut. Only the left-out token's size differs. One is dropped quietly; the other ends training.
  2. Each hit is rare (the sampler must pick a token with q under 1e-4), but a run samples millions of tokens, and decode batches under 8 rows happen at the end of every rollout.
  3. The useful signal is the −inf slot. If the list has one, vLLM's kept set fit inside K, so a miss really is a broken capture (row C). If every slot is finite, the list may be short, so a miss means "drop it", not "crash".

The fix — proposed in review comment C1, not in the PR

Where the fix lands: RL only, one function, check_sampler_support. No vLLM change: keeping ties is vLLM's documented small-batch behaviour.

Row A now has a full list and a miss, so tie_miss is true, the position is marked short, and the loss drops and counts it like row B. Row C has a −inf slot, so tie_miss is false and the raise still fires: the PR's corrupt-capture test keeps passing. The simpler idea, "any miss means short", would break that test, since it would also drop row C. Raising top_logprobs above top_k only makes row A rarer: a tie can be wider than the margin.

So what. As written, replay can end a long run with an error that blames the capture when nothing is wrong. The fix is four lines in one function and keeps the real-corruption check. The review also asks for a unit test with a full list and a tied sampled token.
