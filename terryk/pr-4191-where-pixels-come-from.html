Before

Three pages on this PR. This one: what the feature is and how it compares to the old path.

Background. In SingleController training with token capture, each model call in a rollout is saved as a small row in TQ: only the tokens that are new since the previous call. A finalizer joins those rows into one training row. A vision model also needs pixels, and this PR adds them to the same rows. Dotted words have a short explanation: hover or tap them.

Without capture, RL builds each prompt by running the model's processor itself (nemo_gym_multimodal.py), and the learner trains on those pixels. vLLM runs its own, separate processor on the same images at inference time. With capture, the vLLM worker snapshots what vLLM's processor made (capture_processed_media), packs it into the learner's patch layout (pack_images), and saves it in the same write as the tokens (TQTokenSink.stage). A later call saves only the images that are new. Images it re-sends are checked against the earlier call (size and placeholder tokens) instead of being saved again.

The two paths, one rollout with two model calls

The two paths meet inside the model, at Bridge's _patchify_dynamic_images. It accepts both padded images and already-packed patches, so from there on the math is the same. What still differs is who made the pixels. On the old path it is RL's processor. On the new path it is the processor vLLM ran for generation. With images whose size depends on a token budget, and with video, the two processors can disagree. The PR notes a case where the old video path fails in the learner with 4032 valid placeholders for 2016 projected features. With capture, the learner sees the same pixels the engine saw.

Why keep both

The old path works with any generation backend and any learner, and needs no extra storage. The new path needs async vLLM, the Megatron learner, and the Omni processor with dynamic image sizes, and setup rejects anything else (setup.py:1205-1216, :1257). It stores pixels in TQ for every call. It does not hash pixel contents: a re-sent image is checked only by size and placeholder tokens, so images must not change during a rollout. In the PR's 100-step A/B run, reward, entropy and logprob error matched the capture-off run, and step time went from 44.7 s to 46.2 s.

What to take away. Media capture makes the learner train on the exact pixels vLLM generated from, instead of a second copy made by RL. The data joins the old path inside the model, so nothing downstream of Bridge changes. Before merging, the branch has to be rebased onto main, and one file breaks there without a conflict marker. That is page 3.
