Why the spawned checkpoint worker crashed on a GPU tensor, and how saving the original at import fixes it

NVIDIA-NeMo/RL #4162 · permalinks pinned to head b0134f22, base fd45cb8e, nvidia-resiliency-ext v0.6.0

Before
With SGLang and async checkpointing on, the first save crashed inside the checkpoint worker with AttributeError: … no attribute '_rebuild_cuda_tensor_original'. The save never finished, so the job timed out.
This PR
Saves torch's original rebuild function in a module-level variable when train_utils is imported, instead of on the torch module when the patch runs.
Status

Two pages on this PR — this one: the crash and the fix. The other: how a reviewer's suggestion closes a gap the fix leaves for SGLang's own patch.

To send GPU weights to SGLang, the training process patches torch's tensor pickler so it records each GPU by its UUID rather than its number, since the two processes number GPUs differently (base_policy_worker.py#L224). After the patch, every GPU tensor it pickles is packed as "call _rebuild_cuda_tensor_modified to unpack me". That function fixes up the device number and then calls torch's original rebuild function. Before this PR, it found that original on the torch module, where the patch had stored it (base L78). But the patch only runs in the training process. The checkpoint worker is a separate process that never runs it.

What goes wrong: a pickled tensor lands in a process that never ran the patch

How the fix works

The key fact: unpickling a function by name imports its module. So anything that module sets at import time is guaranteed to exist in any process that unpacks one of these tensors. The PR moves the saved original there.

# Before (base). The original is stored by the patch, on the torch module. def monkey_patch_torch_reductions(): # runs in the training process only reductions._rebuild_cuda_tensor_original = reductions.rebuild_cuda_tensor ... def _rebuild_cuda_tensor_modified(*args): # runs in whatever process unpacks return reductions._rebuild_cuda_tensor_original(*args) # ^ checkpoint worker: attribute never set → AttributeError # After (head). The original is saved when the module is imported. _REBUILD_CUDA_TENSOR_ORIGINAL = reductions.rebuild_cuda_tensor # ^ checkpoint worker: set when unpickling imports train_utils → torch's function def _rebuild_cuda_tensor_modified(*args): return _REBUILD_CUDA_TENSOR_ORIGINAL(*args) # always defined

Real code: before (base L73-L106) · after (head L73-L113) · new test that unpacks in a fresh spawned process: test_utils_smoke.py#L157-L194

Why spawn matters, and where NVRx comes in

NVRx (nvidia-resiliency-ext) is the library that writes Megatron checkpoints in the background, so training does not wait for the disk. NeMo-RL uses its persistent worker: one long-lived process per training rank. The training process sends it each save request, GPU tensors included, through a queue. The queue pickles them with the (patched) pickler (core.py#L514-L541).

How the worker starts decides what it has:

  • fork copies the parent's memory. A child forked after the patch would have the attribute too. NVRx's older one-shot worker forks at each save (core.py#L349).
  • spawn starts a brand-new Python. It only has what its own imports create. The persistent worker uses spawn (core.py#L461), and NeMo-RL requires it, because forking inside a Ray actor is unsafe (setup.py#L2280-L2285).

That is the point of the reviewer's first comment: a value you need later should not live only where "the process that ran the patch, and its forks" can see it, because a spawned process is neither.

💬 review comment — train_utils.py:78 (spawn vs fork)

So what: any setting that turns on SGLang plus NVRx async saves with the persistent worker hit this on its first checkpoint, and the run hung until the scheduler killed it. The fix is safe in every process order: the training process, the checkpoint worker, and the SGLang server all get the original from the import. The one thing the PR stops providing is an attribute SGLang's own copy of this patch still reads. The next page compares the PR with a reviewer's suggestion that restores it.
