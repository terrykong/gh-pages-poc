the −2075 advantage one check or two

Two pages on this PR, one question each — this one: why the same question needs a per-rollout answer and a per-group answer.

Before
Dynamic sampling decided which prompt groups to keep by asking std != 0. A group where every rollout scored the same non-exact reward slipped through, because its std was rounding noise rather than zero.
This PR
Adds a second, separate check that compares a prompt's whole reward group, and uses it for dynamic sampling. The per-rollout leave-one-out check stays, but is used only to decide whether to normalize.
Status
Fixed by this PR. The first attempt reused the per-rollout check for both jobs; a reviewer showed that splits groups, and the author added the separate whole-group check. The final version also fixes a split that was already happening before this PR, when the odd rollout's peers made its std exactly zero.

Two different parts of GRPO want to ask "do these rewards carry any signal?", and they need different answers. Normalizing an advantage divides by the spread of the rewards a rollout is compared against — with leave-one-out, that is the other rollouts, so the question is per rollout (advantage_estimator.py:124). Dynamic sampling throws away prompts that cannot teach the model anything, and it keeps or drops a whole prompt group together, so the question is per group (grpo.py:1957). Using one answer for both jobs breaks the second one.

What each version of the filter keeps

The filter went through three states. "SPLIT" means the group was broken up — some rollouts kept, some dropped — which is never what you want, because the surviving rollouts get re-baselined against each other and lose the contrast that made the group worth training on.

leave_one_out_baseline=True, use_dynamic_sampling=True case status quo PR v1 PR final what you want --------------------------------------------------------------------------------- A [0.95 x8] all same 8/8 0/8 0/8 drop all — no signal B [0.0, 0.95 x7] one differs 8/8 7/8 SPLIT 8/8 keep all — has signal C [1, 0, 0, 0] one success 3/4 SPLIT 3/4 SPLIT 4/4 keep all — has signal D [1, 1, 0, 0] balanced 4/4 4/4 4/4 keep all — has signal E [1 x4] all same 0/4 0/4 0/4 drop all — no signal F [1, 1, 1, 0] one failure 3/4 SPLIT 3/4 SPLIT 4/4 keep all — has signal

Reading the columns:

  • Status quo is wrong two different ways. In A it keeps a group with no signal at all, because the std is rounding noise rather than zero — that is the case the PR author raised. In C and F it splits a group that does have signal, because with leave-one-out the odd rollout's peers are all identical and its std really is exactly 0.0 (0 and 1 are exact in float32, so no rounding is involved).
  • PR v1 fixed A by reusing the per-rollout leave-one-out check as the filter. That fixed the case it was aimed at and added a new split in B — and it still did not fix C or F, which were already broken.
  • PR final gets all six right, because the whole-group check never looks at one rollout in isolation.

So the answer to "one rollout has std = 0 and the rest have std > 0 — should DAPO drop it?" is no, keep the whole group. That single zero is an artifact of leave-one-out arithmetic, not evidence the prompt is useless. The group holds two distinct rewards, which is exactly the contrast dynamic sampling is looking for.

The two checks, side by side

They ask the same question of different sets. The per-rollout one excludes the rollout itself, because that is what leave-one-out means. The whole-group one never excludes anything, so it does not depend on the leave-one-out setting at all.

# per rollout — compares each rollout against its PEERS (utils.py:211) is_trivial_distribution[prompt_idx] = comparison_min == comparison_max # case B -> [True, False, False, False, False, False, False, False] # used only to decide whether to divide by the std # per prompt group — compares the WHOLE valid group (utils.py:241) is_trivial = valid_rewards.numel() <= 1 or (valid_rewards.amin() == valid_rewards.amax()) # case B -> False for every rollout in the group # used only to decide whether dynamic sampling keeps the group

The filter then reads the whole-group answer, falling back to the old std != 0 when dynamic sampling is off (grpo.py:1957), and the whole-group mask is computed once per step next to the baseline (grpo.py:3298):

non_trivial_reward_mask = ( std != 0.0 if is_trivial_prompt_distribution is None # dynamic sampling off else ~is_trivial_prompt_distribution # dynamic sampling on )
Why one check could not do both jobs. With leave-one-out, a rollout's peers can all be the same value while the group it belongs to is not. That is the whole point of the [0.0, 0.95 ×7] case: rollout 1 sees seven identical peers, so it must skip normalizing — but its group is exactly the mixed-reward group dynamic sampling most wants to train on. One answer cannot be both "do not divide this rollout" and "keep this group". Note also that the old std != 0 filter was wrong in the other direction for case A: it kept a group whose advantages were all zero, which is the one thing dynamic sampling exists to prevent.
