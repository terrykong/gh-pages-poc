Six pages on this stack (#4905 and #4979), one question each. This one: how to split a Gym call so both paths run the same code.

Background. NeMo-Gym sends chat calls. On turn 2+, the earlier turns are swapped for the exact tokens the model made (the splice), read from TQ. The clamp fits the output budget. Dynamo's KV router picks a worker by token ids. Dotted words have a short explanation: hover or tap them.

On native, every step runs in one vLLM worker process (VllmAsyncGenerationWorkerImpl). On Dynamo, the KV router needs the final token ids before it picks a worker, so the frontend (NemoRLChatEngine) must plan the call and the worker (DynamoVllmAdapter, wrapping the same class) must run it. That is the only real constraint. So cut the call there, make each side one shared function, and send the plan as JSON.

Same three boxes in both lanes

Across a row, both boxes are one function with the same input and output. Down the Dynamo lane, the plan crosses to the worker as JSON beside the token ids and is rebuilt with ChatCallPlan.from_wire. Gray stays per path: native keeps vLLM's own serving; the adapter keeps its short copy of vLLM's SamplingParams build, since vLLM's serving would render the messages again.

So what. With A and B shared, a fix to the prefix read, the splice, the clamp, capture start or the error map lands once and both paths get it. #4506's restore code then goes into A, B and C one time, instead of into native-only spots that Dynamo copies on the next rebase. What stays per path is small and easy to see: the wire format, and who runs generation.
