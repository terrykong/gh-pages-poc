How score centering cancels the pull that adaptive-ppo-clip's filter adds

Before

This PR
Teaches the centering term adaptive-ppo-clip's keep/drop rule, which depends on the sign of each token's advantage and on the offset k.
Status
Added by this PR. No bug found. Unit tests prove the cancellation for both advantage signs and two values of k; CI is green. The review only adds a docstring nit.

Is this the Microsoft AI method? Yes for one half, no for the other. adaptive-ppo-clip is the entropy-steered clipping from Microsoft AI's MAI-1 paper. The same author added it in #4750. It drops tokens whose ratio is out of range. For positive-advantage tokens the upper limit is hi + k, and after every step k moves to steer entropy toward a target (GRPO guide).

Score centering is a separate fix from #4818: it adds a small extra term so that filtering tokens does not push the policy anywhere by itself. This PR does not touch the MAI method or its k controller. It only lets the two run together, with the centering reading the same k the filter used in that step.

The math: the filter adds a pull, the centering subtracts it

  • p(v): the trainer's probability of token v. Gradients flow through log p.
  • q(v): the sampler's (vLLM's) probability. Known only for its top-k tokens, the head H. The rest, the tail, is modeled as q ≈ ρ·p.
  • r = p/q: the ratio. adaptive-ppo-clip requires force_on_policy_ratio, so this is the token's IS weight, kept raw (no clamp).
  • A: the token's advantage. lo, hi, k, o: the lower bound, base upper bound, offset and outer bound.

Tokens are sampled from q. Average the plain loss's gradient over that sampling and every token v shows up with weight q·w, the kept mass m(v):

\mathbb{E}_{y\sim q}\!\left[\nabla L_{\text{base}}\right] = -A\sum_{v}\htmlClass{t1}{\underbrace{q(v)\,w_A(r_v)}_{m(v)\;=\;p(v)\ \text{if kept, else}\ 0}}\,\nabla\log p(v)

If nothing is dropped, m = p and the sum is zero, since Σp∇log p = ∇Σp = 0. Each dropped token leaves a leftover −p(v)∇log p(v): a pull on that token even when A carries no information. adaptive-ppo-clip keeps a ratio when r ≤ o, and also r ≤ hi + k for A > 0, or r ≥ lo for A < 0. So which tokens leave a leftover depends on the sign of A. The centering term subtracts exactly that sum:

L = L_{\text{base}} + A\sum_{v\in H}\mathrm{sg}\!\left[\htmlClass{t1}{m(v)}-\htmlClass{t4}{\alpha}\,p(v)\right]\log p(v), \qquad \htmlClass{t4}{\alpha}=\mathbb{1}\!\left[\text{tail ratio }1/\rho\text{ kept for this }A\right]

The α part stands in for the tail: its tokens share one ratio 1/ρ, so the filter keeps or drops the whole tail together. With A constant, the sampled-average gradient of L is zero, up to the tail model. The code builds this in score_centering.py.

One token, three advantage signs

Real numbers from the PR's unit test, run through the PR's code. Four-token vocabulary; the head H is tokens 0 and 1 (p = 0.43 and 0.19); the tail is tokens 2 and 3 (p mass 0.38, q mass 0.30). Bounds: lo = 0.5, hi = 2, k = 1 (so hi + k = 3), o = 5.

Read each row left to right. For A > 0, token 0's ratio 4.3 is above hi + k = 3, so it is dropped. Its coefficient is −p(0) = −0.43: the centering pushes back on token 0 by exactly the amount the filter's gap would have pulled it. For A < 0 the lower bound applies instead. Token 1 (0.32 < 0.5) is dropped, and the coefficient moves to it. For A = 0 only the outer bound applies, so nothing is dropped and the coefficients are zero. The tail (1.26) is kept in every row, so α = 1 throughout. ICEPOP (bounds 0.5–2, no sign rule) drops both head tokens for any A. That is why the old mode needed no advantage, and the new one does.

What the PR changes

Where it lands: RL only, three source files. clipped_pg.py moves the keep rule into one shared helper, score_centering.py adds the branch, and loss_functions.py passes the advantages in. The k controller from #4750 is unchanged.

Two details make it correct. The loss filter and the centering call one function, here and here, so they cannot disagree. And the bounds are read on every call (_get_score_centering_is_bounds), not saved once at setup, so the centering uses the k that the controller set for this step.

So what. With TIS and ICEPOP, the filter's leftover pull is the same for every token. With adaptive-ppo-clip it flips with the advantage's sign and moves as k changes. This PR makes the centering follow both, so score_centering: true now works with the MAI-1 method. The unit test test_score_centering_cancels_the_adaptive_ppo_clip_drift checks the averaged gradient is zero for each sign, k ∈ {0, 0.5}, and tails that are kept or dropped. Whether the pair trains better than adaptive-ppo-clip alone has not been measured.
