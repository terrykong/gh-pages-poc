Where do rollout finalizers get their Python environment, before and with this PR?

NVIDIA-NeMo/RL #4760, new flag token_capture.try_reuse_gym_env_for_finalizers. All permalinks pin head ec3c298d.

Before
Finalizers got their own venv folder on every node. It holds the same packages as Gym's folder, so a fresh run builds the same thing twice.
This PR
Adds a flag, off by default. When it is on, finalizers start from Gym's folder and their own folder is never built.
Status
In review. The idea is sound, but the review asks to drop the flag (it gates nothing the registry does not already decide) and to add a timing. The reuse path also has a bug, shown on the next page.

Two pages on this PR, one question each — this one: what the change is and how it compares.

Background. Each Ray actor type runs in its own Python venv. The extras it needs are listed in ACTOR_ENVIRONMENTS, which turns them into a Python command. make_actor_runtime_env(name) builds that venv on every node, in a folder named after the actor. The finalizers and the Gym actor both list only nemo_gym. Dotted words have a short explanation: hover or tap them.

Both actors resolve to the same command, uv run --locked --extra nemo_gym --directory <repo> (registry, command format). So the two folders always hold the same packages; only the folder name differs. Gym's folder is built first, during Gym setup. With the flag on, the finalizer factory asks for Gym's name instead of its own (L203), finds bin/python already there, and returns early (venvs.py L154).

What the flag adds, and what the review asks

The PR turns reuse on only when all three hold: the flag is set, Gym is set up, and the two actors have the same extras and the same Python command (L181–L201). With the code as shipped, the last two are always true: setup refuses token capture without Gym (setup.py L1284), and both actors list the same extras. So the default-off flag is the only thing that decides. The review asks for this shape instead (proposed, not in the PR):

The flag, its two YAML keys, the fingerprint entry and the gym_is_setup argument go away. Both actor names live once, in the actor registry, which is stdlib-only and already imported by this module; nemo_gym.py imports its name from there too. The Python-command check stays, because users may override a registry entry at runtime.
