Three copies of the NeMo-Gym actor setup had three different bugs

Companion illustration for NVIDIA-NeMo/RL #3367 (centralize NeMo-Gym actor construction). Permalinks pin the PR head a77c04e; deleted code is pinned at the base e9a855f.

Three training loops can hand rollouts to NeMo-Gym, an external service that runs environments and returns completions. Each one has to start the same Ray actor: read the env.nemo_gym config block, lift a few keys out of it into top-level fields the actor reads directly, leave the rest for Gym, pick a Python environment, and install the tokenizer. Before this PR all three wrote that sequence out by hand — distillation inline, grpo and SingleController through a shared helper that did it differently. They drifted, and not in the same direction.

Who did what, before the PR

What the PR does about it

It splits the sequence into two functions in one file and points all three call sites at them. The split matters: building the config is now pure — no Ray, no network — so it can be unit tested on its own, which is where the new tests in the PR live.

Does it work?

Nobody has posted a run. There is no W&B link and no before/after number, which is reasonable for a refactor with no speed claim — but it means the only thing standing behind the two behavior changes above is unit tests. So the useful question is whether those tests would notice if the changes were undone. Two of them would not:

break the VLM key lifting (set tokenizer_config=None, drop the image flags) -> 21 passed the suite does not notice drop the enable_router_replay argument on its way to the config builder -> 21 passed the suite does not notice run the suite untouched -> 21 passed

Both gaps are one small test each, and both are cheap: the fixture the new tests share simply does not contain tokenizer_config, so the lifting it was written to prove is never exercised. Those two tests are the change worth asking for before merge.

The takeaway. Nobody wrote three different bugs on purpose. Each copy was correct when it was written, and then a fix landed in one place and not the others — distillation got the Python environment right and never learned about the image-model keys; grpo and SingleController learned the opposite half. Merging them is what makes the two halves meet, which is why a refactor billed as "no behavior change" quietly fixes two things. Both deserve a line in the PR description, so the next person reading the history knows when the behavior actually changed.
