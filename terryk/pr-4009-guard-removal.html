Why the split trainer could stop refusing image batches

Two pages on this PR, one question each — this one: the check that used to reject image batches, and why deleting it is safe.

SingleController trains in small pieces: it calls train_microbatch once per slice of data instead of handing the whole batch to train. Until this PR that method began by refusing any model with images. The refusal listed four things it said the method failed to pass along to the code that builds the microbatches. This PR deletes the check — and the reason that is safe is that three of the four claims were already untrue when the check was written, and this PR supplies the fourth.

Four claims, checked one at a time

Here is the same thing in code. At the merge base the microbatch builder was already being handed three of the four:

) = get_microbatch_iterator( data, self.cfg, state["mbs"], straggler_timer=..., delegate_pack_to_model=self.delegate_pack_to_model, # claim 2 — passed delegate_mtp_loss_mask_to_model=self.delegate_mtp_loss_mask_to_model, # claim 3 — passed model_slices_context_parallel_inputs=self.model_slices_context_parallel_inputs, # claim 4 — passed )

at the merge base, megatron_policy_worker.py:1561-1568 — so only the image-token mask was genuinely absent.

This PR adds exactly that one line, in the same spot the whole-batch train path puts it — after the loss mask is worked out, before the microbatches are built:

attach_media_token_validity_mask(data, self.media_placeholder_token_id) # claim 1 — now passed ( data_iterator, num_microbatches, micro_batch_size, seq_length, padded_seq_length, ) = get_microbatch_iterator(...)

megatron_policy_worker.py:1538, matching the same call on the train path at :873. The mask marks which tokens are image placeholders so the loss skips them.

The check was also failing a test that had nothing to do with images

The check fired on two conditions, not one — images or a model that cuts up its own long sequences across GPUs:

if self.media_placeholder_token_id is not None or ( self.model_slices_context_parallel_inputs ): raise NotImplementedError(...)

at the merge base, megatron_policy_worker.py:1458-1470

That second condition catches a text-only test. One case of an existing test sets exactly that flag and then calls train_microbatch, so it hits the raise every time it runs:

test casesets the flag?result at the merge base
[model-owned-packing]nopasses
[model-owned-cp-slicing]yesraises NotImplementedError

The test is test_megatron_split_state.py:438-475. It arrived first; the check was added later, by #2957, which is the newest commit on the main branch.

The failing case is not hypothetical — it is red on the main branch right now. The unit test job L0_Unit_Tests_Megatron_Policy_1 reports 1 failed, 12 passed, and the one failure is TestTrainMicrobatch.test_forwards_model_owned_packing_flags[model-owned-cp-slicing]. Deleting the check turns it green again, and for the right reason: the microbatch builder really is handed that flag.
So what. Two things travel together here. Removing the check is what lets a model with images train through SingleController at all — that is the point of the PR. It also repairs a test that has been failing on the main branch, because the same check was rejecting a text-only case it was never meant to catch. Worth knowing when reading the diff: deleting a guard usually deserves suspicion, and here the guard's own error message was the thing that was out of date.
