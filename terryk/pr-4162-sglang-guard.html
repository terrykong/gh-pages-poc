the spawn crash what SGLang still reads

Two pages on this PR. This one covers the gap the fix leaves for SGLang's patch. The other covers the crash and the fix.

SGLang ships its own copy of the same torch patch. The two copies share one "already patched" check: if reductions._reduce_tensor_original exists, the patch returns without doing anything (SGLang patch_torch.py#L44-L48, ours L83-L85). Whichever runs first wins. SGLang's check assumes the winner also set both saved originals, because SGLang's rebuild wrapper reads _rebuild_cuda_tensor_original from the torch module (#L80-L82). The PR fixed our wrapper by moving its original into a module variable. SGLang's wrapper still looks on the torch module.

The gap: our patch runs first, SGLang's skips, and nobody sets the attribute

Why no process hits this today. Our patch runs only in the training process (base_policy_worker.py#L224), and weights only travel from training to SGLang, never back. So a tensor packed by SGLang never gets unpacked where our patch won. The reviewer reproduced the crash on real GPU transfer by setting up that order on purpose. The opposite order, SGLang first as in the SGLang server, is fine: our module saves SGLang's wrapper as its "original", and SGLang's wrapper passes our already-converted device number through unchanged (#L89-L91).

The proposed fix: one line, not in the PR yet

Nothing below is implemented. It keeps the promise SGLang's check relies on: whoever sets the flag also sets both originals.

def monkey_patch_torch_reductions(): if hasattr(reductions, "_reduce_tensor_original"): return reductions._reduce_tensor_original = reductions.reduce_tensor reductions._rebuild_cuda_tensor_original = _REBUILD_CUDA_TENSOR_ORIGINAL # proposed # ^ torch's own function here: this module is always imported before its patch can run reductions.reduce_tensor = _reduce_tensor_modified reductions.rebuild_cuda_tensor = _rebuild_cuda_tensor_modified reductions.init_reductions()

Where it goes: train_utils.py#L81-L89 at head.

Afterwards, neither attribute is read by our code. Both exist only for SGLang. A short comment at those lines saying so would stop the next reader from deleting them as dead code. That already happened once in review.
