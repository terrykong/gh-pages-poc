Two pages on this PR. This one compares the PR with the reviewer's suggestion. The other covers the crash and the fix.

SGLang ships its own copy of the same torch patch. Both copies use one "already patched" check. If reductions._reduce_tensor_original exists, the patch returns without doing anything (SGLang #L44-L48, ours L83-L85). So whichever patch runs first wins. SGLang's own wrappers still read both originals from the torch module (#L72-L82). If ours wins, ours has to leave both there.

Three versions, side by side

The PR's column fixes row 4 and breaks row 5. The suggestion keeps row 4 and fixes row 5. Row 5 is latent. Our patch runs only in the training process (base_policy_worker.py#L224), and weights only go from training to SGLang, never back. The reviewer reproduced it on a real GPU transfer by forcing that order.

The suggested code: two lines differ from the PR

Nothing below is in the PR yet. It only changes monkey_patch_torch_reductions().

_REDUCE_TENSOR_ORIGINAL = reductions.reduce_tensor # unchanged: set at import, in every process _REBUILD_CUDA_TENSOR_ORIGINAL = reductions.rebuild_cuda_tensor def monkey_patch_torch_reductions(): if hasattr(reductions, "_reduce_tensor_original"): return # sglang's patch skips itself on this same check, but its wrappers read both # attributes, so whoever wins the check must set both. - reductions._reduce_tensor_original = reductions.reduce_tensor + reductions._reduce_tensor_original = _REDUCE_TENSOR_ORIGINAL # ① same value, one source + reductions._rebuild_cuda_tensor_original = _REBUILD_CUDA_TENSOR_ORIGINAL # ② the fix for row 5 reductions.reduce_tensor = _reduce_tensor_modified reductions.rebuild_cuda_tensor = _rebuild_cuda_tensor_modified reductions.init_reductions()

Head for comparison: train_utils.py#L77-L89

  • ① changes nothing at runtime. Inside the patch, the variable and reductions.reduce_tensor are both torch's function. The module is always imported before its patch can run. If SGLang had patched before that import, the flag would already exist and our patch would return early. The point is that our wrappers and SGLang's wrappers now read the same saved originals, so they can't drift apart.
  • ② is the real difference. It puts back the attribute SGLang's wrapper needs, so the flag again means "both originals are here".
  • The added comment also answers why these attributes stay even though our code no longer reads them. An earlier review question mistook them for dead code.
