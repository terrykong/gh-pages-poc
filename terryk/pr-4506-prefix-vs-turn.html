What prefix recovery keeps that turn recovery throws away

Explainer for NVIDIA-NeMo/RL #4506, part 5 of a stacked series on #5056 (turn-level recovery and deadline snapshots). All permalinks pin the PR head b6aff18. Review comments are in a pending review; their links work once it is published.

Before
Turn-level recovery. A model call that was still decoding at the checkpoint is thrown away; after a restart it runs again from scratch, from the start of its turn.
This PR
Adds rollout_recovery.target_level: prefix. Each checkpoint also saves the tokens every running call has decoded so far, and the restarted call continues from them.
Status
New feature, opt-in. Last round's findings (stop strings, penalties, seeds across a cut) are fixed. Open: with forest training every restored prefix is dropped, and prefix mode cannot start next to restart-only Gym servers. Both are in the review comments. No CI has run on this head yet.

prefix vs turn size and reuse forest training drops the prefix

Three pages on this PR, one question each — this one: what prefix recovery adds next to turn recovery.

Background. In a Gym rollout, an agent server (Gym) calls the model many times. NeMo-RL's vLLM workers answer, and store each finished call's token ids as a row in TQ. Every few seconds the single controller takes a rollout snapshot. With turn recovery, Gym saves its agents in that snapshot, so a restart goes back to the last finished turn (turn recovery, explained). Dotted words have a short explanation: hover or tap them.

At each Gym checkpoint the controller first holds back terminal row writes on every vLLM worker; decoding keeps running (nemo_gym.py:86). Gym then asks each worker to cut its running calls. The worker reads each call's tokens straight from vLLM, under a lock it wraps around vLLM's output step (vllm_worker_async.py:616), and saves the new ones as a TQ chunk row (generation_cut_capture.py:677). After a restart the worker reads those rows back, adds them to the end of the prompt, and lowers max_tokens and min_tokens by the same count (vllm_worker_async.py:2225). It then puts the decoded text in front of the reply (:1538). A call that cannot be cut — the deadline passed, the cut lands inside a multi-byte character, or it uses a setting a resumed call cannot honor, such as stop strings or a seed — falls back to the turn path.

Why keep both. Turn recovery needs nothing from the vLLM worker beyond normal token capture. Prefix recovery needs the vLLM async engine and a Gym build with the cut endpoint, and setup rejects it with multimodal capture or router replay (setup.py:1380). Any call it cannot cut simply restarts the turn way, so turn recovery stays the fallback inside prefix mode.

What it costs, and what is still open

The gain is the decode work up to the last cut: a long call keeps everything it decoded before the checkpoint instead of nothing. The price: with prefix on, the "nothing changed, skip this snapshot" shortcut is off whenever a model call is running (snapshots.py:619), so every snapshot interval holds finished replies on all workers and pauses Gym. The only timing so far is from a 4-prompt, 1-node run (fence held 0.13–0.21 s); the review asks for one at scale.

Open review findings (tracked in the review comments). (1) Forest training drops every restored prefix. With token_capture.forest_training on, the worker rebuilds the admission without the saved cut, so each restored call decodes everything again and its chunk rows stay in TQ (explained here). (2) Prefix mode cannot start next to restart-only Gym servers. Setup tells you to set allow_restart_only_gym_servers, and the config check then rejects that flag because it still only allows turn (config.py:759).
