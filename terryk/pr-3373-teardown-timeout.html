How a NeMo-Gym shard set keeps teardown bounded

Companion illustration for NVIDIA-NeMo/RL #3373 — wire sharded stacks into training. All permalinks pin the PR head 0996e36.

One page on #3373. Background from the PRs below it in the stack: how the shard actors get created (#3371) and how rollouts get routed to them (#3372).

When a training run ends — cleanly or by crashing — something has to stop the NeMo-Gym servers. That happens in a finally block, so it runs even when training already failed. A shutdown that never returns there is worse than a slow one: it replaces the real training error with a job that just sits. shutdown_environments() is the helper every entrypoint calls, and it takes a 10-second limit for exactly that reason (utils.py:149).

This PR changes what gets handed to that helper. It used to be one Ray actor handle; now it is a NemoGymShardSet, a plain Python object that owns several actors. Those two things are stopped in completely different ways, so the helper has to tell them apart — and the limit has to reach both.

Two kinds of entry, two ways to stop them

Why the right-hand path needed the plumbing

Without a limit reaching it, that path has no floor. Gym's own teardown stops each child server on a 1-second then 2-second timer, so that part ends — but the last step waits on the head server with no timer at all, and that wait cannot be cut short:

# Gym: nemo_gym/cli/env.py:622-623 self._head_server.should_exit = True self._head_server_thread.join() # no timeout # Gym builds the server without a shutdown limit — server_utils.py:793-797 uvicorn.Config(app, host=..., port=...) # timeout_graceful_shutdown not passed -> None # uvicorn 0.37.0: server.py:281 passes that None straight through await asyncio.wait_for(self._wait_tasks_to_complete(), timeout=self.config.timeout_graceful_shutdown) # None # uvicorn 0.37.0: server.py:300 — the loop has no clock in it while self.server_state.connections and not self.force_exit: await asyncio.sleep(0.1) # force_exit is set only from a signal handler (server.py:336), and uvicorn # refuses to install one off the main thread (server.py:316). Gym runs this # server in a daemon thread, so force_exit stays False forever.

So the loop's only exit is every open connection closing by itself (uvicorn server.py:300, :316, :336, Gym env.py:622-623). One request that cannot finish — say a call to a vLLM endpoint whose workers are already gone, which is the state teardown runs in after a crash — and nothing below that point returns on its own. The limit has to come from above.

What the code does now

Both halves are in place at the current head. The helper picks the branch by type and passes its limit either way, and the shard set accepts one and hands it to every actor it holds:

# nemo_rl/environments/utils.py:180-185 is_actor_handle = isinstance(env, ray.actor.ActorHandle) try: if is_actor_handle: ray.get(env.shutdown.remote(), timeout=timeout) # timeout = 10.0 by default else: env.shutdown(timeout=timeout) # the plain-object branch # nemo_rl/environments/nemo_gym.py:1620-1635 def shutdown(self, *, timeout: float | None = None, force_kill: bool = False) -> None: shutdown_environments( {...one entry per actor...}, timeout=timeout, # each actor now gets the caller's limit )

The inner call holds real Ray actor handles, so once a limit reaches it the ordinary ray.get(..., timeout=…) and ray.kill() path applies to each one (utils.py:180, nemo_gym.py:1620). There is also a force_kill switch for the callers that want the actors gone regardless (nemo_gym.py:1639).

Worth knowing even when nothing hangs. Gym stops each child server on a 1-second wait, then a kill, then a 2-second wait. A stack with many child servers therefore takes a while to shut down, and the limit is what stops that from growing without bound on the plain-object path. That path is new in this PR, which is why the plumbing had to be added rather than inherited.
