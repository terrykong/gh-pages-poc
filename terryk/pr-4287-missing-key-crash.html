Two pages on this PR, one question each. This one covers the setup crash.

Every Megatron worker (policy, distillation teacher, and the PPO critic, which trains the value model) passes through _validate_training_config, which now reads config["megatron_cfg"]["calculate_per_token_loss"] with no default. Recipes pick up keys from a parent file through defaults:, so a key the root file lacks is missing from every child too. The PPO critic builds its config by copying value.megatron_cfg (setup.py#L3116), and that block never got the key.

The fix — proposed, not in the PR

Where the fix lands: RL YAML files only, no code change. Add the key to each root file, and every child inherits it. The bare read at setup.py#L1942 stays as it is: in this repo, defaults live in YAML, and a missing key should fail loudly.

Nothing below is implemented. It shows the change for the PPO root; the other roots get the same line.

@@ examples/configs/ppo_math_1B.yaml L374-L376 · value:
   megatron_cfg:
     enabled: false
+    # The value loss reads logits, so only true is supported here.
+    calculate_per_token_loss: true
     empty_unused_memory_level: 1

For the critic, true is the only value that works anyway. Its loss, MseValueLossFn, reads logits, and the new check at train.py#L698 rejects logit losses when the flag is false.

So what. As written, this PR stops every Megatron PPO run at critic startup, along with every Megatron distillation run and the Nemo-Gym Nano / Super recipes. That covers L1 tests (ppo_megatron.sh, distillation_megatron.sh) and several nightly and release jobs. GPU CI has not run on this head yet, so nothing has shown it. The unit test test_config_validation.py will fail first. The fix is one line per root file.
