The stall watchdog never asked a NeMo-Gym actor if its servers were alive. Now it asks every one.

PR #5250 · permalinks at head 9859ba83, removed code at base e9193d3d

Before
The watchdog's health check skipped NeMo-Gym in every real run. A dead Gym server showed up only as a generic stall, 600 s later.
This PR
Asks every Gym actor of the shard set, all at the same time, each with its own timeout, and names the actor in each problem.
Status
Fixed by this PR. One design ask is open in the review (C7: move the check onto the shard set class). It does not change behavior.
The single controller runs a watchdog: a background loop that wakes every interval_s (30 s), publishes metrics and looks for a stalled run. NeMo-Gym runs its tool and agent servers as subprocesses inside one or more Ray actors. Those actors form a shard set. Each actor has a health_check that raises if one of its servers has died. Dotted words have a short explanation: hover or tap them.

The old check looped over every environment handle and asked only the ones that have a health_check method (base code). But setup stores the Gym entry as a NemoGymShardSet (setup.py), for sharded and unsharded jobs alike. The set is a plain container, not an actor, and has no health_check. So the check skipped Gym every time. The PR reads the entry as a shard set and asks each actor in it.

One shard set, before and after

The default is gym_subprocess_check: true, so this check now runs in every single-controller Gym run. Two silent or dead actors still cost one 30 s wait together, not two. A dead server's error is cut to its first line, because Gym adds up to 64 KiB of the server's output to it.

The change, as pseudocode

Where the fix lands: RL only, one file. _check_env_health and the new _check_shard_set_health in single_controller.py, plus tests in test_watchdog_pump.py. No Gym change: each Gym actor already has health_check.

Before

# watchdog tick, controller event loop, every 30 s
for name, handle in env_handles.items():
    hc = getattr(handle, "health_check", None)  # a NemoGymShardSet has none
    if hc is None: continue                     # so Gym was always skipped
    await wait_for(hc.remote(), 30 s)           # never reached for Gym

After

# watchdog tick, controller event loop, every 30 s
for name, handle in env_handles.items(): getattr(...)
entry = env_handles.get("nemo_gym")
if entry is None: return []                                                # no Gym in this run
shard_set = as_nemo_gym_shard_set(entry)                                   # a bare actor becomes a 1-actor set
async def check_actor(actor):                                              # one coroutine per actor
    try: await wait_for(actor.health_check.remote(), 30 s)                 # own timeout per actor
    except TimeoutError: return f"{label} did not answer"                  # silent actor
    except Exception as e: return f"{label} unhealthy: {line 1}"           # dead server, Gym text cut to 1 line
problems = await gather(*(check_actor(a) for a in shard_set.all_handles))  # all at once: <= 30 s total

Real code: _check_env_health, _check_shard_set_health, instance_label (the tools/0 names), and the caller in the watchdog loop.

So what. A Gym server that dies mid-run is now named within one watchdog tick (30 s), as instance 'search' reported unhealthy, instead of a generic stall after 600 s. The default stall_action: warn prints it every tick and keeps running; abort ends the run. We checked that a healthy run cannot trip it: the actors finish starting before the watchdog starts, are never restarted, and the watchdog stops before Gym shuts down. The only open review ask (C7) moves this Gym-only code out of the generic loop file and onto NemoGymShardSet.
