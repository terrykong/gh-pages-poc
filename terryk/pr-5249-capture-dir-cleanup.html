Where Gym's token-capture files now live, and who deletes them

NVIDIA-NeMo/RL #5249 · fix(nemo-gym): keep token capture ledgers on node-local disk · head 89a0f59, Gym pinned at 9e2e5d0

Before
With token_capture.capture_dir unset, every Gym actor wrote its capture files under the run's log dir, which is usually on a shared filesystem. Nothing ever deleted them.
This PR
The default moves to a fresh per-run folder on each Gym node's local /tmp, and each Gym actor deletes its own folder when it shuts down.
Status
Fixed by this PR. The team review found no blocking issue. A folder you set yourself is never deleted.
Background. With token capture on, NeMo-Gym records the token ids of every model call in small per-rollout files, called ledgers, so NeMo-RL can train on the exact tokens. Each Gym actor runs all its servers on one node, and those servers are the only ones that open the ledger files. A checkpoint copies the ledger rows it needs into the checkpoint folder (export_model_records), so resume never reads the live folder. Dotted words have a short explanation: hover or tap them.

How the folder is picked, and how it is removed

Where the fix lands: RL only. setup.py picks the folder; _build_gym_actor_config gives each actor its own subfolder plus the run's folder; NemoGym.shutdown deletes it. No Gym change: Gym already creates the folder it is given and never reads it from another node.

Setup, before

# driver, once per run
if capture_dir is None:
    capture_dir = abspath(log_dir + "/gym_token_capture")  # shared filesystem

Setup, after

# driver, once per run
capture_dir_derived = capture_dir is None       # set on every run, so an old value can't stick
if capture_dir_derived:
    capture_dir = abspath(log_dir + "/gym_token_capture")
    capture_dir = _default_token_capture_dir()  # /tmp/nemo_rl-<user>/token_capture/<job>-<8 hex>

Real code: _default_token_capture_dir, setup lines 1598–1601. The random suffix keeps two runs on one node apart, because Gym rollout ids repeat between runs. The new flag is excluded from the resume check (manifest.py), so switching between a set folder and a picked one still resumes.

Shutdown, before

# NemoGym actor, at the end of the run
def shutdown():
    try:     stop_gym_servers()  # SIGINT, then kill what is left
    finally: flush_telemetry()

Shutdown, after

# NemoGym actor, at the end of the run
def shutdown():
    try:     stop_gym_servers()             # SIGINT, then kill what is left
    finally: flush_telemetry()
    if not cfg.capture_dir_derived: return  # a directory you set is never removed
    rmtree(my_dir, on_error=print)          # e.g. .../gym-instances/tools/replica-0
    for parent in my_dir.parents:
        if parent is above run_dir: break   # never touches /tmp/nemo_rl-<user>/token_capture
        try: rmdir(parent)                  # works only when empty
        except OSError: break               # a sibling actor still has files here

Real code: _remove_derived_capture_dir, called at nemo_gym.py:2911.

Worked example: node 2 shuts down

Both actors on node 2 shut down, one after the other. Each one deletes its own folder, then tries to remove empty parent folders, and stops at the first one that still holds something.

actordeletesthen tries to removeresult
tools/replica-0…/tools/replica-0/…/tools/not empty (replica-1 is still there) → stop
tools/replica-1…/tools/replica-1/tools/ → gym-instances/ → 4242-9f3a1c0e/all removed; the next parent, token_capture/, is above the run's folder → stop

Node 1 has one actor, so math/replica-0 removes everything up to 4242-9f3a1c0e/ on its own. /tmp/nemo_rl-alice/token_capture/ stays, ready for the next run.

What changes for you. If you looked in <log_dir>/gym_token_capture after a run to debug, those files are gone now. Set token_capture.capture_dir yourself to keep them; a folder you set is never deleted. Known limits, from the PR: an actor that dies without shutting down leaves its folder behind, and deleting a long run's files has to fit in the 10-second shutdown budget. If /tmp lives in RAM on your nodes, the files use memory until the run ends.
