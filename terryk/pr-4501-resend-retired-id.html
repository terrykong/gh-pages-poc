A Gym row dropped on the last attempt is re-sent under the ID Gym just retired

Review illustration for NVIDIA-NeMo/RL #4501 (harden Gym turn recovery). All permalinks pin the PR head cf124ff.

Before
When a Gym stream ended early, a row it never returned was re-sent under the same rollout ID, while Gym might still be running the first copy.
This PR
Marks those rows as given up, tells Gym to stop them, and re-sends them under a new rollout ID — but only when another row attempt is left.
Status
Open — introduced by this PR, not fixed. On the last row attempt (the default) one path still re-sends the row under its old ID, and the run raises. Raised in the review.
Background. Dotted words have a short explanation: hover or tap them.
  • RL sends a prompt group's rows to Gym in one streamed request. Each row carries a rollout ID.
  • RL tracks every row's current attempt in the recovery ledger. A result can only be saved (sealed) if its attempt is still marked dispatched.
  • While a checkpoint is being taken, Gym may refuse a row at admission.
  • max_gym_row_attempts defaults to 1, so every attempt is the last one.

In _run_rollouts, a stream that ends cleanly but short calls _drop_unreturned_rows with replace=attempt < max_row_attempts. On the last attempt that is False: the missing row's attempt becomes abandoned (abandon_dropped_dispatch), no new attempt is made, and Gym retires the episode. That is fine when the loop then gives up. But if another row in the same stream was refused at admission, the loop takes the admission continue without spending an attempt, and re-sends every row still missing — including the abandoned one, under its old ID.

On the base branch this row stayed dispatched and sealed normally, so the crash is new in this PR. A test reproduced it: events dispatch {2: g7_g2_ac5a…} → retire {g7_g2_ac5a…} → dispatch {1: …, 2: g7_g2_ac5a…} (same ID), ledger row 2 = [abandoned].

What would fix it — proposed, not in the PR

Where the fix lands: RL only, one function. rollout_manager.py · _run_rollouts. No Gym change: Gym already ignores a retire for an episode it no longer has.

Nothing below is implemented. Treat a short clean end like a stream error, so it spends the attempt and the admission retry cannot re-send a row that was just given up on.

With stream_failed set, the if not stream_failed guard skips the admission retry and the loop moves to attempt += 1. Checked with a repro in both modes (sibling and prompt-group); the full test suite was not run with it. Two tempting alternatives do not work: forcing replace=True raises under prompt-group recovery (it rejects replacing one sibling), and it would give the row a free re-send only when a refusal happens at the same time.

So what. With default settings, any stream that ends short while a checkpoint is refusing rows turns a recoverable infra failure into a ValueError in the rollout worker. Gym refuses rows at admission only while it is taking a checkpoint, so this shows up exactly in runs that use Gym checkpointing. Please add a test with a short clean end and an admission refusal in the same stream: one attempt should give the "missing rows" error, two attempts should finish with row 2 under a new ID.
