Why a long multi-turn answer escaped the overlong penalty, and how this PR counts every turn

NVIDIA-NeMo/RL #4487. All permalinks pin the PR head c169600.

Before
The overlong penalty measured only the first assistant turn of a sample. Later turns were never counted.
This PR
Adds up the tokens of all assistant turns, on both places that measure length.
Status
Fixed by this PR. Single-turn runs get the same numbers as before. The review asks for one more change (see the end).
Background. DAPO's overlong reward shaping lowers the reward of answers that run too long. With max_response_length = M and overlong_buffer_length = B, an answer up to M − B tokens keeps its reward. Each token past that costs 1/B of the penalty weight (reward_functions.py:132, L165-168). Dotted words have a short explanation: hover or tap them.

In a multi-turn rollout (tool use, agents, max_rollout_turns > 1), one sample holds several assistant turns with tool or environment output between them. The length is read in two places: apply_reward_shaping scans the message log, and decompose_message_log precomputes response_token_lengths for the data-plane path. Both used to stop at the first assistant turn. So an answer split into many short turns was never penalized, however long it was in total.

One sample, measured two ways

The numbers come from running the real apply_reward_shaping on this sample with a reward of 1.0. The old code returns 1.0 and the new code returns 0.625. The data-plane path gives the same two answers (response_token_lengths 15 before, 27 after).

The fix

Where the fix lands: RL only, two functions. apply_reward_shaping (scans the message log) and decompose_message_log (data-plane path). No config change.

The first hunk replaces "stop at the first assistant turn" with "collect every assistant turn and add them up". The second does the same for the precomputed field, so both paths agree. A new test runs the same two-turn sample through both paths and checks the same penalty (test_reward_shaping_counts_all_assistant_turns).

Who notices. Only runs with reward shaping on and more than one assistant turn per sample. They will see more overlong penalties and may need to retune max_response_length. No shipped example config has both, so no shipped recipe changes. Open in review: the sum also counts assistant turns that arrive as part of the prompt history, which the policy never wrote. The review asks to count only turns that carry generation_logprobs, the same marker the loss mask uses.
