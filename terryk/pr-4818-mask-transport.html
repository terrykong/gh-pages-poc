Five pages on this PR, one question each — this one: which route a sampling mask can take.

Background. A sampling mask is one short list of token ids per generated token. In token capture mode, the driver no longer reads per-token data out of Gym's reply: it switches to receipt mode and skips the function #3937 reads the mask in. Dotted words have a short explanation: hover or tap them.

Same 3 generated tokens, both routes

Example: top_k=4, top_p=0.8. Supports of size 3, 2 and 1 for the 3 tokens. #4818's lane uses K=2 recorded candidates.

What replay on the token-capture route needs — proposed, not in any PR

Where it would land: RL only. Copy #4818's pattern for its two columns. No Gym change in token-capture mode: the tensors skip Gym, and top_k is pinned on the vLLM server (#3937 does this, because Gym's Responses API cannot send top_k). Gym needs work only for the token-capture-off route.

Nothing below is implemented. It is a sketch of where each piece would go.

A possible shortcut, not tested. With logprobs_mode=processed_logprobs, vLLM computes the reported log-probs over the filtered logits, so tokens the filter cut come back as -inf (model.py L255, sampling_mask.md). So #4818's own columns with top_logprobs = top_k would already hold the support: the ids whose log-prob is finite. Two things stop that today: #4818's extraction rejects any non-finite log-prob (extract_score_centering_samples), and setup forbids filters with score centering. Ties at the top-k edge would also need checking.

So what. Asking Gym to carry the mask only helps runs with token capture off. For token-capture runs, the mask should ride the route #4818 just built, and Gym needs no change. #3937 is a draft from August, written against an older main, so it needs a rebase either way. #4818 is not the place to add this, but its staging slot for per-token columns is the piece mask replay would reuse.
