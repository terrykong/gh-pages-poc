Seven pages on this stack, one question each. This one: the feature checklist.

Background. NeMo-RL picks a refit method with policy.generation.refit_transport (options). NCCL reshard, NIXL and delta (sparse) refit are faster ways to do the same copy. Fleet health watches the inference servers NeMo-RL launched. #4674 accepts only refit_transport: null (factory), and inside that, only NCCL. Dotted words have a short explanation: hover or tap them.

The red rows

  1. Keeping the KV cache doesn't work. SingleController already pauses before refit with the user's recompute_kv_cache_after_weight_updates setting. The synchronizer then pauses again with clear_cache=True, and vLLM accepts a second pause. So with the setting at false, every kept request still recomputes its whole prompt after each step. The synchronizer also resumes serving before SingleController finishes its own refit bookkeeping.

    🟡 review comment C6 — remote_vllm_nccl_weight_synchronizer.py

  2. v1 GRPO isn't refused. A v1 run with backend: remote_vllm gets past setup and crashes later, after the cluster is allocated.

    🔴 review comment C1 — nemo_gym.py

  3. FP8 servers aren't checked. The external backend never asks for KV-cache scale calibration (requires_kv_scale_sync stays at its default False). Preflight never reads the server's quantization from /server_info. An FP8 server would run with stale scales.
  4. Router replay isn't refused. Details are on the NeMo-RL code in vLLM page.

The comment links work for others only after the review is published. It is still pending.

Leaving room for faster refit — proposed, not in the PR

Nothing below is implemented. NCCL is fixed in three places today: the config (transport: Literal["nccl"]), the factory (always returns the NCCL synchronizer), and preflight (requires the server's backend to be nccl).

Where it lands: RL only. Make the factory pick the synchronizer from remote_vllm_cfg.refit.transport, and make preflight compare the server's backend to that value. Then vLLM's own sharded_rdt (closest to reshard) or sparse_nccl (send only changed values) can be added later without touching the rest. NIXL and NeMo-RL's XOR delta format would still need code running inside vLLM. The shared-package idea is where that code would live.

So what. For a first PR, refusing most features is the right call: each refusal is a clear startup error. The problem is the four red rows, which fail late or quietly do the wrong thing. Two are already in the pending review (C1, C6). FP8 and router replay need one startup check each.
