What a failed rollout adds to MoE expert-load counts, and how much this PR removes

Before
A failed rollout still becomes a training row (with zero loss weight), and its tokens were counted when Megatron balances expert load. Main's #4503, merged while this PR was open, already stops counting padding, which leaves one token per failed rollout.
This PR
Marks those rows is_artificial_input and drops them from the expert counts. Real rows with zero loss weight still count.
Status

Two pages on this PR, one question each. This one: what the PR removes from the counts.

Background. Some MoE models keep an expert bias. To update it, Megatron counts how many tokens each expert received during the training forward pass. It skips every token marked True in padding_mask, and it counts only while gradients are on (router.py:812-820). So whatever lands in a training batch, including rows with zero loss weight, moves the bias unless the mask hides it. Dotted words have a short explanation: hover or tap them.

How the PR marks the rows

The key rule: a row is left out because of where it came from, not because its loss weight is zero. The middle row above has zero loss weight too, and it must still count. So the PR carries one flag per row from the place that makes the placeholder down to the mask:

  1. The reassembler sets tag["is_artificial_input"] = not row.valid on every published row (rollout_reassembler.py:757-758).
  2. The flag rides in the row's tags and is turned back into a bool tensor when the worker fetches the batch (codec.py:461-466).
  3. When the mask is built, flagged rows are OR'd in: mask | is_artificial_input (router_mask.py:49-52). On this tiny batch, row 3 goes from [0,1,1,1] to [1,1,1,1].

Steps 1 and 2 are the part main does not have, and they should stay. Step 3 is built on a second copy of the mask code; page 2 shows why that copy should go and the OR should move into main's mask. The same mask also keeps these rows out of the router's aux loss and z-loss, not only the bias counts (router.py:931). That is probably what we want, but the PR description doesn't say it.

So what. The rule is correct, and a per-row tag is the right way to carry it. Simpler options like "skip rows with zero loss weight" would wrongly drop real truncated or filtered rows. But on main the remaining effect is one token per failed rollout per MoE layer. That rarely changes a bias update, so this is a small cleanup, not an urgent fix. The PR should shrink to the tag, the flag lift, a few-line OR into main's masks, and a test that checks expert counts.
