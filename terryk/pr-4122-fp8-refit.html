What changes in a TensorRT-LLM weight refit when rollouts run in FP8

NVIDIA-NeMo/RL #4122 (Qwen3.5 routed-expert block-FP8 / MXFP8 refit). All permalinks pin the PR head 6908199.

Before
TensorRT-LLM rollouts ran only in BF16. Every refit copied the trainer's BF16 weights into a BF16 engine as-is.
This PR
Adds trtllm_cfg.precision: fp8. The trainer still sends BF16; the inference worker turns the MoE expert weights into FP8 (plus scales) on arrival.
Status
New feature, proposed in this PR. The default setup is consistent end to end. Setting quantization_ignore_patterns has a bug — see the second page.
FP8 refit vs BF16 refit ignore patterns cast FP8 into BF16

Two pages on this PR, one question each — this one: how the new path compares with the existing one.

Background. A refit copies the trainer's new weights into the inference engine after each training step. With TRT-LLM on separate GPUs, the trainer broadcasts BF16 tensors over NCCL and each inference worker loads them. Dotted words have a short explanation: hover or tap them.

The trainer side does not change: it sends the same BF16 tensors it always sent. Two things change on the inference side. At startup, the engine is built with an FP8 quantization config and empty weights (configure_fp8_llm_kwargs). On every refit, the worker converts the incoming expert weights before loading them (load_model_weight_func). Both paths then end in the same TRT-LLM call.

What still differs after they merge

Only the dictionary handed to reload. In BF16 it holds one fused tensor per projection. In FP8 it holds one tensor per expert and projection, each with a weight_scale_inv partner, and the engine's FP8 expert layers read those scales. Everything around the call is shared: the NCCL receive, the begin/finish weight-update calls, and the prefix-cache reset. Two FP8-only guards are new: setup checks that something will actually be quantized (validate_routed_experts), and a refit that fails halfway marks the worker as unusable instead of serving a mix of old and new weights (_abort_weight_update_after_failure).

Why keep both. BF16 is the reference and needs no extra choices. FP8 halves the bytes of every expert weight, which is where most of a MoE model's weights live, but the rollouts now sample from a slightly different model than the one being trained. The PR does not yet show how large that gap is (no reward or gen_kl_error curves), so that is the main open question for this feature.
