Nine pages on this stack — this one: #4265: a config that crashes on the first batch.

The three switches involved

  • Capability discovery: its own docstring says it runs "without enabling saves", so it looks safe to turn on by itself.
  • Token capture: only when it is on does RL put _ng_rollout_id and _ng_attempt_index on each row.
  • Turn-level checkpointing: what the new per-rollout bookkeeping is for. #4266 requires token capture for it, and also, through a chain of checks, for discovery: discovery needs a snapshot interval, and a snapshot interval needs token capture.
Dotted words have a short explanation: hover or tap them.

The new bookkeeping in run_rollouts turns on when discovery has found Gym servers, not when turn-level checkpointing is on. It then reads the two row keys that only token capture adds.

Same setup, token capture on and off

How the first rollout crashes, step by step

  1. The config passes the check. With discovery on, setup checks only the number of Gym actors, not whether token capture is on.
  2. Setup runs discovery (setup.py), which fills in the list of Gym checkpoint participants.
  3. Rows are built without the ID keys. RL adds _ng_rollout_id and _ng_attempt_index only when token capture passes rollout IDs. Here it is off.
  4. The new tracking code turns on anyway. It checks only that the participant list is non-empty, which discovery made true.
  5. It reads the missing key (row[_NG_ROLLOUT_ID_BODY_KEY]) and raises KeyError: '_ng_rollout_id' on the first batch.

The config that crashes, and why nothing stops it:

rollout_checkpointing: gym: capability_discovery_enabled: true # "without enabling saves" token_capture: enabled: false # rows carry no _ng_rollout_id
  • This PR's config check only checks the Gym shard count.
  • #4266 closes the crash: discovery needs a snapshot interval, and a snapshot interval needs token capture. So it needs this PR without #4266.
  • What stays true with #4266: discovery on with turn-level checkpointing off is a valid config. Every row still registers with the Gym actor and fetches a receipt that nothing uses.
  • The same gate also turns on a per-row receipt fetch (nemo_gym.py:1904) that nothing ever uses in discovery-only mode.

What would fix it — proposed, not in the PR

Where the fix lands: RL only. A new flag, set in setup.py from the turn-level checkpointing setting (today the config field #4266 adds, config.py:760 there), and read at the two gates in nemo_gym.py:1843 and nemo_gym.py:1904. The target-level proposal on #4266 replaces that field with rollout_recovery.target_level: turn. No Gym change. The switch arrives in #4266, so the fix can land there.

Nothing below is implemented. Turn the bookkeeping on with the switch it serves, turn-level checkpointing, instead of "discovery found servers". Setup already knows that switch; it only has to pass it to the actor.

# setup (proposed): pass the switch into the Gym actor actor_cfg["turn_level_checkpointing"] = cfg.gym.participant_checkpointing_enabled # False; target_level == "turn" under the proposal # nemo_gym.py run_rollouts, at the gate (proposed) if self._turn_level_checkpointing: # False → skip registration register(row["_ng_rollout_id"], row["_ng_attempt_index"]) # same check before the receipt fetch at :1904 # result: discovery-only runs the rollout with no extra per-row work

Real code this changes: the gate at nemo_gym.py:1843, the receipt fetch at nemo_gym.py:1904, and the actor config built in setup (the switch itself is added by #4266).

So what. In the stack, the KeyError cannot happen: #4266 refuses discovery without a snapshot interval, and a snapshot interval without token capture. It needs #4265 on its own. What is left is smaller: turning on discovery by itself, which its docs describe as "look, don't change anything", still makes every row register with the Gym actor and fetch a receipt nobody uses. Gating that work on turn-level checkpointing fixes it, and that switch arrives in #4266. Under the target-level proposal, discovery runs on every token-capture run, so this gate matters for every run below target turn.
