Two pages on this PR, one question each. This one: what moves where, before and after.

Background. A refit copies new weights from training to the generation engine after each step. With refit_transport: nccl_reshard, the big FFN weights (gate, up, down, dense and MoE) go on a bulk path: one point-to-point NCCL transfer per weight, resharded from training layout to generation layout. Everything else goes on a misc path: a packed broadcast loaded through the engine's normal weight loader. Each side describes each weight with a LocalParamSpec: pre builds the send/receive buffer, post commits it. Dotted words have a short explanation: hover or tap them.

The example is one MoE expert's gate_proj weight, shape [768, 2048], stored as Transformer Engine blockwise FP8 (one scale per 128×128 block, so a [6, 16] scale grid). It goes to a vLLM engine also running blockwise FP8. On the PR side, the source hook pre decodes and picks the BF16 wire dtype. The vLLM hook _blockwise_fp8_receiver_quant_spec quantizes the weight again on arrival.

So what. The transfer loop no longer cares how either side stores a weight. That is why this PR could delete refit_payload_mode and the source cache, and allow format pairs main rejected. The price is 2× wire bytes for FP8 sources. There is no FP8 timing after the change yet; the review asks for one. Also, the receiver now computes scale shapes itself, where vLLM's loader used to.
