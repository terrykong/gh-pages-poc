Four pages on this PR. This one covers what is still too big after the author's fixes.

With router replay on, each cut saves the expert route rows for the tokens decoded since the last cut. vLLM keeps a running request's routes as a list of small pieces that it only appends to. A cut takes that list from the same read that copies the tokens. Commit 352f46c4 then adds a buffer that doubles when full, so a cut copies only the new pieces (absorb_engine_route_pieces). One function later, frozen_cut_routed_experts joins every row into a cumulative tensor that its only caller unpacks and never reads.

What one cut copies

The buffer is worth having only once the unused copy is gone. Until then it adds ~55 source and ~90 test lines with no time saved. It has no timing numbers, and the PR description says this stack goes "correctness first, optimization last". So the review asks for the copy to go here, the buffer to go to #4508 (the stack's I/O speed-up PR), and timing numbers for it there. #4508 is already rebased on this PR and still carries both.
