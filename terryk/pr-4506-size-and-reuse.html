Six pages on this PR, one question each — this one: what can go.

Background. With target_level: prefix, each rollout snapshot asks every vLLM worker to save the tokens its running calls have decoded so far, as chunk rows. When a call finishes, the worker writes its full terminal row and deletes its chunk rows. That delete is the only write that can break a snapshot in progress: Gym's snapshot may still point at those chunk rows. Dotted words have a short explanation: hover or tap them.

The biggest cut: the snapshot fence

To keep that delete out of the snapshot window, the PR closes a gate on every worker from the snapshot's start until the TQ save is done. Every terminal write waits, so a call that finishes inside the window cannot return its reply. The gate needs begin/end calls on the worker, VllmGeneration and the interface, plus GenerationCutFence. The PR's own notes say the terminal write itself is safe; only the delete is not. So queue the delete instead.

Why the proposed order is safe. The driver already waits for the fence to begin before Gym prepares its snapshot (async with order), so the list swap at the start of snapshot N+1 always runs after snapshot N's TQ save. Rows swapped out belong to calls that had already finished. Gym acknowledges a finished call through its terminal row only (terminal ack), and exports only this round's cuts (Gym export), so snapshot N+1 never names those chunk rows. A terminal row written mid-window is already accepted: validation runs with clear_unreferenced=False (snapshots.py:421) and restore clears extra rows (restore.py:466). One cost: if a worker restarts, its list is lost and those rows wait for the next restore to clear them.

Where the change lands: RL only. The worker keeps a list of chunk-row keys to delete; the three delete sites append to it; the begin/end pair becomes one call that GenerationCutFence.held awaits before Gym prepares. No Gym change: Gym already acknowledges finished calls through their terminal row. It also removes the gate that #4655 would otherwise build on before a later PR deletes it.
