Where the fix lands: RL only, one file. vllm_worker_async.py. No Gym or vLLM change: vLLM already offers an output mode that carries every token so far.

Why the accumulators exist: for prefix runs the PR switches vLLM to DELTA output, then writes ~95 lines to glue the pieces back into one reply. CUMULATIVE output gives the whole reply at every step, so the worker only needs to skip the tokens it has already seen. It already keeps that count in observed_generation_token_count.

What each piece does, in order: (1) ask vLLM for the whole reply at every step (:1769); (2) save only the new tokens, using the count the capture state already keeps (generation_cut_capture.py:107); (3) go back to the base code's final_res = res, and put the restored prefix in front of the last output only (:1846); (4) delete the two classes (:226). Do not use vLLM's RequestOutput.add instead: it drops routed_experts, which router replay (#4612) needs. Two costs to check: the log-prob helper still reads the whole output each step, and vLLM's slow-tokenizer path copies the text each step.

So what. About 300 of the 2,007 source lines, and 55 test lines, repeat code that already exists. Applying these before the next PRs in the stack build on the same files keeps the feature smaller everywhere above this PR. One open design question, not a finding: the snapshot fence (~250 source lines) and #4655's 253-line cleanup module both exist so that a finishing call can delete its chunk rows while a checkpoint is being taken. Was moving that delete to a point outside the checkpoint considered? If it was, the PR body should say why it does not work.
