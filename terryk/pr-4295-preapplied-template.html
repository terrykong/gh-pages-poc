Mark pre-templated samples with chat_template_preapplied, and tokenize them with the loop NeMo-RL already has

Before
get_formatted_message_log always applies the tokenizer's chat template. Energon sources whose text is already templated would be templated twice.
This PR

Two pages on this PR. Page 2 shows the bug in the PR's own tokenizer, which this design deletes.

Some Energon sources in an SFT blend hand over messages whose text already has the chat template in it. NeMo-RL must not apply the template again, but it still needs it for every other source in the blend. Only the cooker that reads such a source knows this, so it marks the sample, and the tokenizing loop skips just the one step that applies the template. Why not policy.tokenizer.chat_template: null: that turns the template off for the whole run, not for one source.

A cooker for a pre-templated source (for example a file-backed cooker from #4296) returns CanonicalSFTSample(..., chat_template_preapplied=True); nothing else in the blend changes. _join_text_parts keeps the PR's support for content given as a list of text parts, which the adapter's _normalize_messages can produce.

Things that behave differently from the PR's helper

  • A task prompt, tools or a generation prompt now raise. They would change text that is already final; the helper silently dropped the first two.
  • BOS/EOS follow the normal flags and are only added when missing (L719, L739), the same as for templated text today.
  • The text is joined in the loop, not rendered through apply_chat_template, because the DeepSeek-V4 tokenizer wrapper replaces that method and would add its own markers.
  • Tokenizers that add a leading-space marker (Mistral v0.3, Llama-2) give each turn after the first a leading space, the same as the chat-template path does. Qwen2.5, Llama-3.1, Gemma-2 and Nemotron-Nano-9B-v2 decode back exactly.
So what. The feature stays and gets a name that says what it means. The PR's separate tokenizer, and the bug in it (page 2), go away: pre-templated text goes through the same per-turn tokenizing as every other source, and a cooker opts in with one field.
