Two pages on this PR, one question each. This one: where the metric-name list should live.

Every training step, an algorithm hands a dict like {"reward": …, "loss": …} to Logger.log_metrics. That fans it out to W&B and friends, then calls tee_rl_metrics_to_otel, which copies some keys into OTel. Which keys, and under which OTel name, is decided by a fixed table, _TRAIN_SCALARS, that lives in the telemetry package and spells each algorithm's key by hand. The metric names themselves are now NeMo-RL's to choose — lens (the telemetry library) added a registry for exactly that, which the PR's own comment says "removed the blocker". So the question is not whether to send these, but who writes the list.

Today: one table in telemetry names everyone's keys

What goes wrong: rename one key

Say GRPO renames its logged "reward" to "reward_mean". W&B follows the new name at once. OTel does not:

# grpo.py — the author edits the log line metrics = {"reward_mean": rewards.numpy(), …} # was "reward" # telemetry/metrics.py — untouched, still looks for the old word _TeedMetric("reward", "reward_mean", "rl.reward.mean") map_teed_scalars(metrics) → {} # rl.reward.mean gets no points # the drift test that is meant to catch this "reward" in rollouts.py:541 # result["full_result"]["reward"] = … test_every_teed_logger_key_is_emitted → PASS # found the word, wrong dict

Links: map_teed_scalars · rollouts.py:541 · _metric_dict_keys (the search). "loss" and "grad_norm" are weaker still: each shows up as a key in more than 15 files.

What would fix it — proposed, not in the PR

Nothing below is implemented. Telemetry keeps the tee and a small registration call; each owner declares its rows next to the line that logs them.

# nemo_rl/telemetry/metrics.py — machinery only @dataclass(frozen=True) class TeedMetric: logger_key: str name: str # registry key = name.removeprefix("rl.").replace(".", "_") kind: str = "gauge"; unit: str = ""; description: str = "" def register_teed_metrics(rows): … # owners call this; rows are collected, then handed to lens # ONCE on the first tee (lens raises on a second registration) # nemo_rl/algorithms/grpo.py — beside the loop that logs these keys REWARD_KEY = "reward" GRPO_TEED_METRICS = (TeedMetric(REWARD_KEY, "rl.reward.mean"), TeedMetric("kl_penalty", "rl.kl.divergence"), …) metrics = {REWARD_KEY: rewards.numpy(), …} # one name, used in both places
Why it matters. The list lives in the one package every algorithm depends on, so each new algorithm or backend has to edit telemetry to get its metrics out. Silence is the failure mode: a rename sends the OTel series flat while CI stays green. Lens now lets NeMo-RL name its own series, so moving each row next to the code that logs it costs only a move. Nothing is lost. If that move is too much for this PR, the smaller step is to take the training-metric table out and land it later in the owner-declared shape, which is what #3655 agreed to.
