Two pages on this PR, one question each. This one: why the PR has to be rebuilt on main's mask.

Background. Nemotron Omni slices its own CP inputs: it sets model_slices_context_parallel_inputs = True (Bridge :174) and cuts padding_mask with the same index as input_ids (:768). So NeMo-RL only has to hand it the full, unsliced mask. Dotted words have a short explanation: hover or tap them.

One recipe, two code paths

The PR's own test expects this raise: the case (packed, model slices CP, CP=2) is listed as "must raise" (test_router_mask.py:121-124). CI won't show it, because the recipe is in disabled.txt. The new required model_config argument also breaks main's existing callers that don't pass it.

Proposed fix — not in the PR

Where the fix lands: RL only. Keep main's mask path and add only the flag, in hybridep.py and data.py. (plus the IS_ARTIFICIAL_INPUT import). Then delete router_mask.py, the model_config argument and its 7 call sites, the guard, and the end-of-function mask block. No Megatron change: MCore already skips every True position in padding_mask.
