What fsdp_output_dtype: bfloat16 changes: the tensors between layers stop being float32

NVIDIA-NeMo/RL #4115 (feat(automodel): expose FSDP output precision). Permalinks pin the PR head 5a9638c; upstream links pin Automodel 72dacef and torch v2.13.0.

Before
The DTensor (Automodel) backend always told FSDP to cast every layer's output, and the final logits, to float32.
This PR
Adds policy.dtensor_cfg.fsdp_output_dtype. Leaving it out keeps float32. Setting bfloat16 keeps those tensors in bf16.
Status
Proposed in this PR — opt-in, default unchanged. The branch needs a rebase, and the memory saving has not been measured yet.

Two pages on this PR, one question each — this one: what bf16 outputs change, and where both paths meet.

Background. Automodel wraps each decoder layer, and the whole model, in its own FSDP unit. A mixed-precision policy tells each unit which dtype to do the math in and which dtype to hand its output to the next unit. This PR only changes the second one. Dotted words have a short explanation: hover or tap them.

NeMo-RL builds one policy for the whole model in setup_distributed: math in bf16, gradients summed in float32, and outputs in whatever fsdp_output_dtype says (read here, checked here). Automodel gives every decoder layer that same policy (parallelizer.py), and torch casts each unit's output on the way out (_post_forward). The next layer casts its input straight back to bf16 (_cast_forward_inputs), so the float32 copy between layers holds no extra digits.

Same model, two settings — one example: 8,000 tokens, hidden size 4,096, vocab 128,256

Where the saving shows up, and where it does not

The logprob step makes a float32 copy of the logits. With no chunking it copies all of them at once. With chunking it copies 1,000 tokens at a time (0.51 GB here). So the logit memory in the logprob step is:

logit tensors alivefloat32 outputs (before)bf16 outputs (this PR)
no chunking4.10 GB (cast is a no-op)2.05 + 4.10 = 6.15 GB
chunks of 1,000 tokens4.10 GB2.05 + 0.51 = 2.56 GB

Layer outputs halve in both cases. After the two paths meet, three places still see bf16 instead of float32, and the PR's field comment names them (__init__.py:204): value and reward-model losses, which read the logits without a float32 cast; the in-place temperature divide (train.py:245); and moe_parallelizer.lm_head_precision, whose float32 logits the outer unit casts back to bf16.

So what. bf16 outputs hold the same digits the layers computed, and in a small CPU test the gradients matched float32 outputs exactly. The memory win is real when logits are chunked. With no chunking, the logit step uses more memory. Measure on 2 or more GPUs: on one GPU the setting does nothing. float16 outputs are a different story — see page 2.
