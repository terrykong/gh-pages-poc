Who watches what when a generation engine dies

Companion illustration for NVIDIA-NeMo/RL #3590 (part 2/4 of the SingleController resiliency stack). All permalinks pin the PR head cff673e.

The confusing part of this PR is that it looks like three watchers doing the same job. They are not. The GenerationFleetMonitor is a ledger — a plain-Python table of per-shard health that watches nothing by itself. Two things write facts into it: a probe loop that asks every serving vLLM shard "are you alive?" every 5 seconds (single_controller.py:718), and the generate path, which reports failures it hits on real requests (vllm_generation.py:910). Three things read it: the shard picker for the next request, the membership push to the NeMo-Gym router, and the watchdog. The watchdog is a different animal — it does not care about shards; it checks one number every 30 seconds (how long since any rollout finished?) and kills the run if the answer is "too long" (:715). On the NeMo-Gym path there is one more piece: a router actor that all Gym requests flow through. The ledger's serving set is pushed into it — the router itself asks nothing and reports nothing back.

One dead engine, step by step

Two shards, default settings: probe every 5 s, 3 failures to condemn, floor of 1 serving shard. Kill shard 1's engine at t=0.

If shard 0 also died, the watchdog's floor check would end the run with GenerationFleetExhausted — the failure names the cause. Without this PR, the only backstop is the stall watchdog noticing silence minutes later and saying RolloutStall — true, but it names the symptom. A restarted engine does not come back on its own: answering probes again proves nothing about its weights, so re-entry requires a completed weight sync (that machinery lands in parts 3–4 of the stack).

What to remember. The "monitor" never acts on its own — it is a ledger that two observers write and three readers consult. The watchdog stays even with fleet health on, because it answers a question no per-shard probe can: is the run as a whole still making progress? And if you enable the Gym router without fleet_health.enabled=true, nothing ever updates the router's serving set — it stays health-blind forever (the review asks for a warning on that combination).
