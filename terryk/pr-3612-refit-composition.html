Keeping SGLang refit code out of the policy-worker constructors — the change, with a working diff

Review companion for NVIDIA-NeMo/RL #3612. The change described here exists as a diff: terrykong/RL#25 (one commit on top of #3612's head f4d36ef). Problem permalinks pinned to b86aa8e.

#3612 adds SGLang weight refit for the Megatron policy backend. Two pieces of it put SGLang-specific code where no other generation backend has any: the training-side worker constructors now branch on the generation backend to create connection state and install a serialization patch, and a new 96-line file re-implements the Megatron→HF weight walk and the bucket packing that already exist in the repo. Both are avoidable with the patterns already in these files, and the fix is a net deletion: 5 files changed, +69 −171.

The two pieces, and the in-repo pattern each one skipped

Piece 1 — constructor state. Both policy workers gained an if backend == "sglang": block in __init__ (megatron_policy_worker.py:654, dtensor_policy_worker_v2.py:377) that creates _sglang_ipc_state, four _sglang_dist_* fields, and installs monkey_patch_torch_reductions(). The pattern the same file already uses for vLLM is lazy: stream_weights_via_ipc_zmq calls self.maybe_init_zmq() on first use and carries nothing in the constructor.

Piece 2 — a private copy of the weight walk. MegatronSGLangHfWeightIterator walks bridge.export_hf_weights and packs results into byte-budgeted buckets. Both halves already exist and are already used by other transports: _iter_params_with_optional_kv_scales is the same walk feeding the vLLM ZMQ and collective transports, and iter_named_tensor_buckets is the packing the FSDP2 SGLang path in this same PR already composes (dtensor_policy_worker_v2.py:1163).
