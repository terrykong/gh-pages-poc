Keeping backend-specific refit code out of the policy workers — a composition proposal

Design proposal against NVIDIA-NeMo/RL #3612. Code permalinks pinned to b86aa8e.

#3612 makes the Megatron policy worker — the training-side class — carry SGLang-specific code in two places: its constructor now creates SGLang connection state and installs a serialization monkey patch when the generation backend is SGLang (megatron_policy_worker.py:654), and a new file re-implements the Megatron→HF weight walk just for SGLang (megatron_sglang_weight_iterator.py). No other generation backend needed either. This page shows why the repo already contains the right seam, and a design that generalizes it — so the next backend adds one file in its own package and touches the policy workers zero times.

The seam already exists — the PR walked past it

The vLLM impl takes any iterator of (hf_name, tensor) pairs. Both policy backends can already produce one — Megatron via export_hf_weights, FSDP2 via dtensor_params_generator. That iterator is the narrow waist: every transport ultimately ships HF-named tensors, and every policy backend can emit them. Fuse the two sides — as #3612 does — and you get one class per (policy × transport) pair. Keep them apart and you get one piece per side:

The contract — three small interfaces

1. The source — each policy backend implements exactly one method. Both bodies already exist in tree; this only names them uniformly:

class BasePolicyWorker: def iter_hf_weights(self, *, kv_scales=None) -> Iterator[tuple[str, Tensor]]: raise NotImplementedError # declared once, on the base # MegatronPolicyWorker: body of _iter_params_with_optional_kv_scales (export_hf_weights walk) # DTensorPolicyWorkerV2: body of dtensor_params_generator(self.model, self.dtype)

2. The transport plugin — a picklable object, owned by the generation backend's package. The driver builds it once; Ray ships it to every policy worker. It never subclasses the worker and never reaches back into it — everything it may touch arrives in a context:

class RefitTransport(ABC): # nemo_rl/weight_sync/transport.py key: str # "sglang-ray-ipc", "sglang-broadcast", ... requires: str = "hf_full" # or "tp_local" (megatron-inference reshard) def setup(self, ctx) -> None: ... # once per engine topology; may install # monkey patches, build gather/NCCL groups def transfer(self, ctx, req) -> None: ... # once per refit def teardown(self, ctx) -> None: ... # at shutdown; destroys groups @dataclass class WorkerRefitContext: # built worker-side, per call rank: int world_size: int weights: Callable[..., Iterator] # = worker.iter_hf_weights state: dict # worker._refit_state[transport.key] @dataclass class RefitRequest: # per-refit arguments, all picklable buffer_size_bytes: int weight_version: int engines: list # Ray actor handles serialize fine engine_lock: Any quantization: dict

3. The worker dispatch — one generic method on the base worker. This is the whole policy-side surface; it never grows again:

class BasePolicyWorker: def run_refit_transport(self, transport, phase: str, req=None): ctx = WorkerRefitContext( rank=self.rank, world_size=self.world_size, weights=self.iter_hf_weights, state=self._refit_state.setdefault(transport.key, {}), # unconditional dict ) return getattr(transport, phase)(ctx, req) # setup / transfer / teardown

The synchronizer keeps its current driver-side role — engine lifecycle, pause, KV invalidation — and stops needing four backend-named policy methods:

Inside SGLangRayIpcTransport.transfer, the pipeline is source → transform → pack → ship, with the two middle stages shared code:

def transfer(self, ctx, req): tensors = ctx.weights() # source (backend-agnostic) tensors = self.transform.apply(tensors) # Bf16Passthrough today; # Mxfp8Quantize in #3614 — and it works # for BOTH policy backends automatically for bucket in iter_buckets(tensors, req.buffer_size_bytes): # ONE bucketing impl self._ship_bucket(ctx, req, bucket) # gather + IPC serialize + Ray call — # today's send_hf_buckets_via_ipc_actor_impl

Against the nested-classes sketch (SglangWeightSynchronizer.MegatronSide / DtensorV2Side / SglangSide): that shape works, but it is the fused matrix with better labels — adding mxfp8 for FSDP2 still means writing a new Side, and each Side pair must agree on a private protocol. The plugin design needs one new piece per new thing (a source, a transport, or a transform), and the pieces meet only at the iterator.

Honest caveats. This is a paper design validated against every call site named above, not code that has run — no GPU here. Two real asymmetries to respect: Megatron's export walk is collective, so a rank-0-only transport must still drain the iterator on every rank (#3612 already handles this; it moves inside the transport's transfer), and megatron-inference resharding ships TP-local shards, not HF tensors — hence the requires capability rather than forcing everything through one iterator shape.

The compromise actually asked for in #3612 — none of the plugin design above; just consistency with what the repo already does, so no ground is broken:

That is the whole in-PR ask: one dict on the base, lazy init in the connect methods, one file deleted. The plugin design stays a direction for later — worth adopting the day a 4th backend or the mxfp8 transform makes the fused shape cost real duplication again.
