Four pages from the #3925 review — this one: the two problems left after the fix commit.

Three review comments, two problems. The thread reply and the first pending comment describe the same thing from two anchors — the thread where the ask was made, and the new code that answers it. The second pending comment is separate and small. Both are about one new guard, so the page shows that guard first.

The fix commit adds _validate_restored_sampler_cursor, called once in run() right after the three restores (:598-605). It collects every target_step stamp from the restored replay buffer and from the recovery ledger, and refuses to start if the sampler cursor is behind the largest one — the one state that used to make re-admission drop prompts. The guard is correct, and two new tests pin it (reject and accept).

Problem 1 — the guard reads a field the test double does not have

AttributeError: '_FakeTQBuffer' object has no attribute 'target_step_list' single_controller.py:991 TestReplayBufferPersistence::test_run_restores_native_tq_replay_metadata_without_payload_reput TestReplayBufferPersistence::test_run_missing_native_replay_metadata_starts_empty TestReplayBufferPersistence::test_run_restores_native_replay_state_with_in_order_sampler TestReplacementReservePersistence::test_run_restores_the_pool_when_replay_metadata_is_absent TestReplacementReservePersistence::test_run_without_a_reserve_file_starts_with_an_empty_pool tests/unit/single_controller + test_logger.py + test_rollout_manager.py at a3dfa6c: 5 failed, 1084 passed

The fix is one line in the fake, right after self._metadata_state is set, derived from the same state the fake's count_for_target_step already reads, so the guard sees what the real buffer would report:

self.target_step_list = [group["target_step"] for group in self._metadata_state["groups"]] # default state has groups=[] → [] → the guard finds nothing to check and returns

Problem 2 — two of the three admission sites got the new guard

The same commit replaces the old “drop the surplus prompts” branch with _require_unoccupied_target_step, which raises if a freshly admitted step already has groups in the buffer. A target step is minted in three places; the guard landed in two.

Severity. Problem 1 blocks: it turns the lane that runs tests/unit (L0_Unit_Tests_Other) red, and the fix is one line in a test double. Problem 2 is a low-severity consistency note, not a bug. Neither changes production behaviour.

One intended consequence of the guard is worth a sentence in the RolloutCheckpointConfig docstring: a checkpoint written before the sampler cursor was saved (pre-#3480) whose buffer has stamps now fails at startup instead of silently dropping prompts later. That is the right trade — it should just be written where someone hitting the error will look.
