How detached MTP heads keep the right gradient scale when the loss drops sequences

NVIDIA-NeMo/RL #5095, stacked on #5080 (in-loss filtering). All permalinks pin the PR head a0185fd3.

Before
Turning on loss_fn.seq_logprob_error_in_loss with any MTP config failed at startup with an error.
This PR
Allows it when MTP heads are detached, and divides the MTP gradients by the token count from before filtering, in both trainers.
Status
New in this PR. The math is correct in both trainers. One existing unit test now fails because the PR adds a value to a reduce that test checks (review C1, below). Attached heads are still rejected.
Background. MTP heads are small extra layers trained next to the policy. With detached heads, their loss changes only their own weights (output weight, hidden state, tagging). In-loss filtering drops bad sequences inside the training loss, so the number of surviving tokens is only known at the end of the step. Dotted words have a short explanation: hover or tap them.

The two losses see different tokens. The policy loss counts only the surviving tokens (K). The MTP loss mask is token_mask × sample_mask, built before the forward pass (train, split path). The filter never touches it, so MTP sums over all tokens (G). Each sum must be divided by its own count. Since only MTP weights get the MTP gradient, the PR can fix their scale on its own.

\text{policy grad} = \frac{1}{\htmlClass{t1}{K}}\sum_{\text{kept tokens}}\nabla\ell \qquad \text{MTP grad} = \frac{1}{\htmlClass{t2}{G}}\sum_{\text{all tokens}}\nabla\ell_{\text{mtp}}

K: tokens that survive the filter. G: tokens before filtering. The step that fixes MTP is always the ×K/G on MTP-tagged weights only, by _scale_mtp_param_grads.

One batch, two trainers, same result

The change

Where it lands: RL only. grpo.py lets detached MTP through the check; megatron_policy_worker.py fixes the scale in both trainers. No Megatron-LM change: detached heads already keep the MTP gradient off shared weights.

In the SingleController trainer the policy count and the pre-filter count share one DP all-reduce, so no new collective is added. The draft counts move one slot to the right; draft training is still rejected with in-loss filtering, so that slice is empty here.

So what. Detached MTP now works with in-loss filtering. The author measured a 19% faster step on an MoE model with 5 MTP heads, and reward and MTP acceptance stayed within one step-to-step standard deviation. Two things to know. (1) MTP now also trains on sequences the threshold rejects. In the separate-pass mode those are dropped from MTP too, so switching modes changes MTP's training data. (2) The PR adds a third value to the all-reduce, but an existing test still expects two values, so it fails (review C1).
