Where the single-controller actor runs on a Slurm cluster — with and without the new pin

NVIDIA-NeMo/RL #5051 (pin the SingleController actor to the dedicated Ray head) · review · permalinks pin the PR head 365c591 and Ray 2.58.0.

Before
With DEDICATED_RAY_HEAD=1, Ray's default rule already puts the controller on the GPU-free head whenever the head has a free CPU.
This PR
Makes the controller request the head's ray_head resource, so it can run only there. Adds an env var to turn that off.
Status
Open: keep the hard pin; the review asks for a clear error when the head is full. Requiring the head is the intent. In the rare case the head has no free CPU (case 3 below), the run fails with an error that blames the wrong thing.
Background. In single-controller GRPO, one CPU-only Ray actor, the controller, runs the training loop; its host memory can peak at hundreds of GB. ray.sub's DEDICATED_RAY_HEAD=1 keeps the first node free of GPU work so it has room for that peak. Dotted words have a short explanation: hover or tap them.

The controller asks Ray for num_cpus=1, num_gpus=0 (single_controller.py:399). For such an actor, Ray's default scheduler first tries only nodes with no GPUs (hybrid_scheduling_policy.cc:183-220; scheduler_avoid_gpu_nodes defaults to true). On a dedicated-head cluster the head is the only such node, so the controller goes there. The PR adds resources={"ray_head": 1} (run_grpo_single_controller.py:101-105), which only the head has, so the controller can go nowhere else. The two rules agree until the head has no free CPU.

Three cluster states, two ways to place the controller

The two rows differ only in case 3. In case 1 there is no ray_head, so neither rule turns on; the failed job the PR cites was this case, and DEDICATED_RAY_HEAD=1 is what moves it to case 2. Case 3 needs every head CPU taken by actors created earlier, such as the router. It is rare, but with the hard pin the controller stays PENDING and the driver's liveness check ends the run after stall_timeout_s (600 s by default), blaming the event loop.

What the review asks — proposed, not in the PR

Where the change would land: RL only, one example script plus its test and doc. _controller_placement. The pin stays as written.

The env-var opt-out goes, since the head is always where the controller should run. The liveness check already gives up after stall_timeout_s, so no new timeout is needed; it only needs to tell "never started" apart from "stopped answering":
