Three pages on this PR. This one: how much of the current head the test needs.

The test reads the rows each run trained on from the trainer's own dump (load_training_records), then checks each restored call: it finished once, it starts its row's last call, and its first tokens hash to what the restore logged (_assert_prefix_boundary). Every other row must match the uninterrupted run exactly. Those checks are worth keeping. The extra lines are checks that cannot fail, the same lookups built several times, and unit tests that repeat each other.

Two checks that can never fail (C17, C18)

Where the fix lands: RL only, test files only. _gym_prefix_recovery_parity.py and the matching unit tests. No product change.

prefix + tail = total. The vLLM worker computes the logged total as exactly that sum (vllm_worker_async.py:1914-1931). The author removed this check in round 1, and the last commit brought it back. Advantages within tolerance. GRPO computes each row's advantage from its prompt group's rewards and masks (advantage_estimator.py:106-145), and the test already compares rewards, masks and group membership exactly. With top_p=1e-6 every advantage here is 0 anyway.
