Three pages on this PR, one question each — this one: which exits lose the last save.

As first pushed, with the flag on, a save was published only by _finish_pending_save. The train loop calls it at the top of each step and once more, blocking, after the loop (L3906). But a run limited by epochs ends differently: when the data is used up, the last step is marked final and saves (L3725), the loop goes round once more, finds nothing to train, and leaves through a plain return that skips L3906. The GRPO example config ends this way: max_num_epochs: 1, max_num_steps: 1000000.

The last two steps of a 2-step run, with and without the flag

  1. Step 2 is the last step because the data is used up, so it saves. With the flag on, the save is only marked pending.
  2. The loop condition only checks max_num_steps, so the loop runs once more. Its first poll comes right after the save, so the write is not done: False.
  3. No batch is left, so the loop returns and never reaches the blocking finalize after it.
  4. run()'s cleanup calls CheckpointManager.shutdown(). The manager was never told about the pending save, so it does nothing.

An error in the step after a save takes the same route to the cleanup, in both the SingleController and SFT v2, and drops the save the same way. On main, that cleanup publishes it.

The fix — landed in this PR (5f93e1bae)

Where the fix lands: RL only, two functions. Each loop now publishes a still-pending save in its teardown, before checkpoint close. One spot covers every exit: the early return, errors, and cancellation. The finalize after the loop stays; the teardown call does nothing once no save is pending.

What is left — proposed in the review, not in the PR

_finish_pending_save clears the pending save before waiting for the checkpoint lock. If teardown cancels the train pump during that wait, the workers have already finalized, but the new teardown publish finds nothing pending and tmp_step_N/ stays. Nothing below is implemented: clearing it inside the lock, right after the rename starts, closes the gap.
