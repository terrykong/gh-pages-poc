think-tag check: capture vs echo grad written into the logits

Two pages on this PR, one question each. This one covers the new penalty path.

Background. In GRPO with NeMo-Gym there are two ways to get rollouts back. On the echo path, Gym returns chat messages with token IDs. On the token-capture path, Gym returns the exact token IDs vLLM sampled, plus a list of spans, and a finalizer rebuilds the rows. The think-tag penalty sets the reward to 0 when the model writes <think>/</think> where it should not. Dotted words have a short explanation: hover or tap them.

Both paths decide the thinking mode from the prompt. If the prompt ends with an open <think>, thinking is on, and the model must write exactly one </think> and no <think>. If the prompt's tags are balanced, thinking is off, and the model must write neither. Echo does this per (user, assistant) message pair. Capture does it per (carry, generation) span in the new has_malformed_think_tag. In the example below, token 7 is <think> and token 8 is </think>.

Where they meet: the ID rule and the string rule are the same on both paths. What still differs: only Gym's message-level flag, which capture has no source for. A follow-up issue (asked for in the review) would let both paths share one predicate.

The one gap both paths share

When the tag IDs are known and thinking is off, the ID check expects 0 close tags. The text check still allows 1 (count(close) > 1). So if the model spells </think> with ordinary tokens (for example " </", "think", ">"), neither check fires:

carry      [.., 7, 8]           → open=1 close=1 → thinking off → expect (0, 0)
generation "Answer </think>"   → IDs (0, 0) ok · text close=1, allowed up to 1 → not penalized

Echo has the same > 1 rule. Whether Gym's flag catches it there depends on how vLLM's reasoning parser splits the text, and that was not checked. This PR copies echo's rule, so it does not make anything worse.

So what. Token capture can now use the think-tag penalty with the same rules as echo, and the rules are saved so a resume with different tags is refused. The shared gap is small. The fix for both paths: compare the decoded close count with the count the ID check expects (0 or 1), and keep "at most 1" only when the IDs are unknown.
