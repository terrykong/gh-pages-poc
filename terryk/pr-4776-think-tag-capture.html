Three pages on this PR, one question each. This one: the think-tag penalty.

Background. A reasoning model first thinks, then answers: <think> plan </think> answer. When thinking is on, the chat template already puts <think> at the end of the prompt, so the model should write exactly one </think> and no <think>. When thinking is off, the template puts an empty <think></think> in the prompt, and the model should write no tags at all. The think-tag penalty sets a rollout's reward to 0 when the model breaks this, so training stops rewarding broken output. A rollout comes back from Gym in one of two formats, shown below. Dotted words have a short explanation: hover or tap them.

Here is one coding-agent rollout with two turns. In each turn, some new prompt tokens arrive (the task, or a tool result), and then the model writes some tokens. The echo path gets this as chat messages: a user message with the new prompt tokens, then an assistant message with what the model wrote. The token-capture path gets the exact token list vLLM saw and sampled, with no messages. Instead, Gym adds a list of spans: one pair of lengths per turn, (new prompt tokens, model tokens). The new code walks the list with those lengths and cuts out the same turns.

The rule, with inputs and outputs

For each turn: look at the new prompt to decide if thinking is on, then count the tags the model wrote. It counts twice. First it counts the special tag tokens. Then it turns the model's tokens back into text and counts the tag strings, because a model can also spell </think> out of ordinary pieces like </ think >, which the token count cannot see. What still differs, and the one gap

EchoToken capture (this PR)
Where the tag text comes fromGym's text for each replyRL turns the tokens back into text with the tokenizer, so it now loads one, only when this penalty is on
Extra Gym flagGym also flags any tag inside the final answer textNot available: there are no messages to flag. The docs say so.
Resume from a checkpointnothing savedThe tag settings are saved, and a resume with different tags is refused

The gap is the last table row above: thinking off, and the model spells </think> from plain pieces. The token count expects 0 and sees 0. The text count allows up to 1 on every turn, even though a thinking-off turn should allow 0. So nothing fires. Echo has the same rule, so this PR does not make anything worse. The fix for both paths: when thinking is off, allow 0 close strings, not 1.
