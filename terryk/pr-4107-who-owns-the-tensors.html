Who owns the tensors a worker just fetched?

On NVIDIA-NeMo/RL #4107. All links pinned to 4fb9fbc.

Before
Every read from the in-process store handed back a fresh copy, so what a worker did to a batch stayed in that worker.
This PR
Drops the copy and returns the stored object itself. That is the speedup, and for plain tensors it is safe.
Status
Open — not fixed in this PR. Nothing fails today: the one type that breaks it cannot reach the one worker that would trigger it. Raised in review.

Three pages on this PR, one question each — this one: what a worker can accidentally do to the store.

Workers read training batches from a small store that lives in the same process. This PR removes the copy that used to happen on the way in and on the way out. Follow one batch from the writer to the GPU — every box below links to the line that does it.

One batch, from the writer to the GPU

Steps 2 and 3 are the two lines this PR changes. Step 5 is where the field types stop matching: lines 1119 and 1121 are the same text, and the whole difference sits inside each .to().

Why nothing fails today

Step 4 is the catch: that call lives in the DTensor worker, and this data never reaches it. The only shipped writer is Energon vision-language SFT, and sft_v2.py:399-400 raises "SFTv2 supports only the Megatron policy backend." The Megatron worker never moves a whole batch — it goes straight to get_microbatch_iterator, so its device moves land on slices it built itself. The only .to("cuda") in that whole file is optimizer state, not batch data.

So this is a hazard, not a failure — it starts costing the day someone lifts that one-backend limit. It also breaks an assumption already written down: the docstring on PackedTensor.to says a bad device move cannot happen because worker-side moves “happen post-serialization on independent copies.” Steps 2 and 3 are what made them independent.

What would fix it — proposed, not in the PR

Nothing below is implemented. This is the change suggested in review.

Let the shortcut at step 3 skip PackedTensor, so that one type falls through to the branch below it, which already builds a new wrapper:

# nemo_rl/data_plane/adapters/local.py:104 - if _is_identity_indices(indices, _value_batch_size(value)): + if not isinstance(value, PackedTensor) and _is_identity_indices( + indices, _value_batch_size(value) + ): return value

One line. PackedTensor then reaches local.py:112 — value.slice(indices).

The speedup survives, because slice shares the image data instead of copying it:

fetched = store.slice([0, 1, 2, 3, 4]) fetched is store False # a new wrapper — the store is safe fetched.tensors[0] is rows[0] True # same image data — nothing copied store.tensors[0].device cpu # after the worker's move to the GPU
The fix costs less than the copy it replaces. Measured on one machine's CPU, so read it as a ratio, not as throughput: on a 64-row value holding 86.7 MB of images, slice takes about 0.001 ms against about 3.2 ms for the deepcopy this PR deletes. Plain tensors skip the check and keep the full speedup.
