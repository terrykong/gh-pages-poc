Three pages on this PR. This one: every struct and helper on the media path, sorted into shared, copied, and backend-only.

The answer is mostly good news. Everything that stores, checks, reads back or joins pixels is one shared set of code (the 5 media columns, validate_media_tensors, _resolve_media). The prompt splice was widened to accept a set of end-of-sequence tokens instead of being forked. The copies are all in the step that works out "which images did earlier turns already save", which is new code in this PR.

The second gives the row counter and slice_media_tensors one rule to call. The slicer can then take the patch size from StagedMediaTensors.patch_size instead of dividing areas. The other two copies need no new code: pass the engine payload itself plus attachments= the way vLLM does (but only after the Gym re-pin, since the fork's adapter still reads a field the copy hides), and move the two MINF_* keys into token_capture.py.

What to take away. The PR is not inventing a parallel pipeline. It reuses every piece that stores and joins pixels. It does add four small copies, all in new code and all cheap to fold back now, before a third backend copies them again. The two ways of answering "which images did earlier turns save" look alike but are different jobs, and should stay two.
