Two pages on this PR, one question each. This one: how GTP gets turned on.

Background. NeMo-RL builds each Megatron model from a Bridge model provider. model_overrides copies any field the provider accepts in its constructor. Bridge's finalize() computes the GTP size itself. Dotted words have a short explanation: hover or tap them.

Bridge declares gtp_weight_remat_size: int = field(init=False, default=1), meaning it cannot be passed in, and computes it from tensor_parallel_num_weight_shards (transformer_config.py:173-176, :204-218). Megatron-LM calls the shard count "the user-facing knob" (model_parallel_config.py:56-67). NeMo-RL's override merge only accepts fields that can be passed in (setup.py:1248), but the PR's driver helper reads only gtp_weight_remat_size (lm_policy.py:78-88). The PR's test calls that helper on a plain dict, so it never meets Bridge (test_gtp_config.py).

Two ways to ask for GTP 3, neither reaches the PR's code

What would fix it: proposed, not in the PR

Where the fix lands: RL only, three places. A typed tensor_parallel_num_weight_shards field in MegatronConfig; always set on the provider in _apply_parallelism_config, like TP and CP; and read by the driver helper for the world-size check only. Setting it every run matters because a provider loaded from a checkpoint can carry a shard count saved at a different TP. No Bridge change: Bridge already derives GTP from the shard count.

Nothing below is implemented. The expert-side setting (expert_tensor_parallel_num_weight_shards) gets the same treatment.

With config B and this change, the driver sees GTP 3 and rejects a world size that is not a multiple of TP × GTP = 12 before any worker starts. The test should run the real _merge_model_overrides on a Bridge provider and compare its finalized GTP size with this helper.

So what. As written, no config turns GTP on through this PR's code: the key it reads crashes every worker, and the key that works is invisible to it. GTP data still lands on the right GPUs with the working key, because the layout NeMo-RL already had handles it (page 1). Reading the real setting fixes the world-size check; page 1's fix removes the code that would hang once this is fixed.
